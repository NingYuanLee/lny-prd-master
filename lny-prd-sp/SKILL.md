## 与总控的关系

全流程见 **`lny-prd-master/SKILL.md`**。本步为 **⑨ `/lny-prd-sp`**：按 **版本** 汇总估点。须先有阶段 1 信号；建议在 **⑦ check** 产品链可估之后执行。完成后控制权交还总控。

# 版本故事点 `/lny-prd-sp`

## 本步职责与禁止

| 负责 | 禁止 |
|------|------|
| 解析 **版本号**；读该版信号与（若有）台账 | 修改 `main_spec` / `api` / `ui` / `feature` / `pages_prd` 正文 |
| 按本文权重表计算 FE_SP / BE_SP | 改 `*_changes.md` / `eval_signals.md` |
| 覆盖写入 `versions/{版本号}/sp_report.md` | 写 DDL、人天、HTTP/JSON；把权重散写进其它 Skill |
| **同版本可重跑**：再次执行本步时 **直接覆盖** 该版已有 `sp_report.md`（不保留历史副本、不改版本号） | 为重跑新建版本目录或追加第二份报告 |
| 产品链不可估时写报告并 **停算** | 在根规范「变更记录」表新增行 |

**原理与公式说明书**：仓库 **`README.md` →「2.1 可评估性 → 阶段2」**；本文只给可执行权重与步骤。

## 输入变量

```yaml
版本号: v1.0.0   # 必填语义；未指定则取 versions/ 最大版本，报告抬头须写明实际使用版本
```

- `versions/{版本号}/` **必须已存在**；否则停止并提示先 **①** 或 **⑧**。

## 计分范围

| 条件 | 计分对象 |
|------|----------|
| 无 `ui/api/feature_changes.md`，或三表皆无有效变更行 | **全量**：根规格中 **active**（或未标 deprecated）的 PAGE / FEATURE / API / EXT |
| 任一台账存在有效变更行 | **仅本版台账条目**对应对象；对该对象贡献乘 **变更形态 × 存量数据影响** 系数 |

## 权重表（默认，可后校准）

档位：`低=1` / `中=2` / `高=3`。

### FE（①～⑦，与 check 同号）

> **①** 为非 AD 页计数；**②～⑦** 均 **按单页** 计分，各页小计再加总。

| 分项 | 算法 |
|------|------|
| ① 页基线 | 每纳入的 **非 AD** 页 `+1`（终端编码 ≠ `AD`） |
| ② API 数量档位 | **单页**：本页 API 条数映射：`少量`(0～1)=`0.5` / `一般`(2～3)=`1.5` / `较多`(4～6)=`2.5` / `极多`(≥7)=`3.5`（§5 或 PAGE 关联） |
| ③ API 请求编排类型 | **单页**：`单请求或并行=0.5` / `串行=1` / `串并行混合=1.5`（`pages_prd` §7；缺则记 0 并标 FE 信号不全；旧值 `单请求`/`并行` 按本档计） |
| ④ 页面交互体验档位 | **单页**：`简单=1` / `标准=2` / `较复杂=3` / `极复杂=4`（`ui/PAGE` 或 manifest；旧值低/中/高→简单/标准/较复杂） |
| ⑤ 页面视觉细节档位 | **单页**：`粗糙=1` / `标准=2` / `精致=3` / `极精致=4`（`ui/PAGE` 或 manifest；旧值低/中/高→粗糙/标准/精致） |
| ⑥ 功能数量档位 | **单页**：本页关联 FEATURE 个数映射：`少量`(0～1)=`0.5` / `一般`(2～3)=`1.5` / `较多`(4～6)=`2.5` / `极多`(≥7)=`3.5`（§6 或反查） |
| ⑦ 流程角色 | **单页**：`主流程=1.5` / `支线=1` / `辅助=0.5` / `设置=0.5`（`pages_prd` §7） |

单页 FE 小计 = ①～⑦ 对该页贡献之和（① 对该页贡献为 `1`）。版本 `FE_SP` = 纳入计分的各页小计之和（迭代时再乘该页台账系数）。

### BE（①～⑦，与 check 同号）

> **①⑥⑦ 独立**；**②** 为 API 清单与总数基线；**③④⑤** 对 **② 中每个单 API** 分别计分后加总。

| 维 | 算法 |
|:--:|------|
| ① | **独立 · 页数（仅AD）**：纳入计分的 AD 页去重数 × `0.5`（全量：`ui_manifest`/FEATURE 关联中终端=`AD`；迭代：台账涉及的 AD `PAGE-*`） |
| ② | **API 总数**：纳入计分的 `API-*` 去重数 × `1`（全量：active；迭代：台账涉及的 API）；同时为 ③④⑤ 的对象集合 |
| ③ | **单 API · 服务对象**：对 ② 中每个 API：`前端视图`/`资源管理` → `+1`；`前端视图和资源管理` → `+1.5` |
| ④ | **单 API · 数据操作形态**：对 ② 中每个 API：`单对象查询`/`简单写入`=`1`；`多对象关联查询`/`多对象写入`=`2` |
| ⑤ | **单 API · API是否涉及第三方联动**：对 ② 中每个 API：`否`=`0` / `是`=`1`（为「是」须挂 EXT，缺口标 BE 信号不全） |
| ⑥ | **独立 · EXT 对接**：每个纳入的 EXT × 对接复杂度(1/2/3) |
| ⑦ | **独立 · FEATURE 分支数与验收标准(AC)条数**：每个纳入的 FEATURE：`分支数×0.5 + AC条数×0.2` |

版本 `BE_SP` = ①～⑦ 之和（**不**乘持久化档；表结构细活实现后校准，报告可注一句）。迭代时：台账涉及对象的贡献先算再乘该行系数。

### 迭代系数（仅「本版变更」模式；连乘）

| 变更形态 | 系数 | 存量数据影响 | 系数 |
|----------|------|--------------|------|
| 新建 | 1.0 | 无 | 1.0 |
| 复制扩展 | 0.4 | 需迁移 | 1.3 |
| 修改 | 0.6 | 需备份或回滚预案 | 1.2 |
| 废弃删除 | 0.5 | | |

同一对象多行台账：系数取 **各行连乘结果的最大值**（避免重复惩罚过度；并在报告注明）。

## 门禁

1. **产品链**（STORY→FEATURE→AC→PAGE→API 关键环，同 check §3.1）：不可估 → 仍写 `sp_report.md`，结论「不可估」，**不输出数值合计**。
2. **FE 信号不全**：`FE_SP` 记 `—`，表内列缺口。
3. **BE 信号不全**：`BE_SP` 记 `—`，表内列缺口。
4. 任一侧为 `—` 时，版本「合计」记 `—`（或仅输出有分的一侧并注明）。

## 前置条件

- 已执行 `/lny-prd-master`；存在 `main_spec.md`
- 存在 `versions/{版本号}/`
- 建议已跑 `/lny-prd-check` 且产品链可估（非强制，但不可估则停算）

## 执行步骤

1. 解析 `版本号`（未指定 → `versions/` 最大 semver）；校验目录存在
2. 判定计分范围：读三台账是否有有效行 → 全量或本版变更
3. 读信号：`ui_manifest`/`ui/PAGE`、`pages_prd`（该版本）、`feature/`、`api/`、`eval_signals.md`（若有）
4. 产品链门禁；不可估则按模板写报告（§1～§3 数值为 `—`）并结束
5. 按权重表计算 FE / BE；迭代模式乘系数
6. **覆盖写入** `versions/{版本号}/sp_report.md`（UTF-8）；若文件已存在则 **整文件替换**，允许同版本反复估点
7. 对话中回报路径与版本汇总三行数字（或 —）；**不**改 `iteration_notes`（除非用户明确要求记一笔流水——默认不写）
