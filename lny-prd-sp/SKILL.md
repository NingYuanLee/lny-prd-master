## 权重表（默认，可后校准）

档位：`低=1` / `中=2` / `高=3`。

### FE（①～③，与 check 同口径；**纯按页 · 对标 BE**）

> **FE ≠ BE**：FE **三维**，只评 **非 AD** 页（按页计因子；报告 §2.1～§2.3 **分维分表**）。BE 按 AD 页 / API / EXT / FEATURE **分对象四维**估，维号独立。  
> **原则**一句；**算法**列只写总公式，因子细则见下方各维分表。  
> **角色基线**：`主流程` `1.5` / `支线` `1.0` / `辅助`·`设置` `0.5`。**② 页面体验**：简单·粗糙 `0`；标准 `0.5`；较复杂·精致 `1`；极复杂·极精致 `2`。功能数量 / API 数量 / 请求编排相对上一档表 **整体 -0.5**。

| 维 | 名称 | 原则 | 算法 |
|:--:|------|------|------|
| ① | 页面定位 | 越主流程、单页功能点越多，页侧定位越重 | （页面角色基线 + 功能数量档）× 迭代系数（细则↓） |
| ② | 页面体验 | 交互与视觉越精，前端还原越重 | （交互体验 + 视觉细节）× 迭代系数（细则↓） |
| ③ | 页面数据 | 本页接口越多、编排越串，前端对接越重 | （API 数量档 + 请求编排）× 迭代系数（细则↓） |

#### ① 页面定位：计分因子

| 因子 | 取值 → 分 |
|------|-----------|
| 页面角色基线 | 读 `pages_prd` §7 流程角色：`主流程` → `1.5`；`支线` → `1.0`；`辅助`/`设置` → `0.5`。缺角色 → 记 0 并标 FE 信号不全 |
| 功能数量档位 | `少量`(0～2)=`0` / `一般`(3～5)=`1.0` / `较多`(6～8)=`2.0` / `极多`(≥9)=`3.0`（按本页 FEATURE 个数）；优先 §6，否则 §7「关联 FEATURE」，再否则 PAGE↔FEATURE 反查；多源不一致 → **信号矛盾** |

#### ② 页面体验：计分因子

| 因子 | 取值 → 分 |
|------|-----------|
| 页面交互体验档位 | `简单` → `0`；`标准` → `0.5`；`较复杂` → `1`；`极复杂` → `2`；读 `ui/PAGE` 或 manifest；旧值低/中/高 → 简单/标准/较复杂 |
| 页面视觉细节档位 | `粗糙` → `0`；`标准` → `0.5`；`精致` → `1`；`极精致` → `2`；读 `ui/PAGE` 或 manifest；旧值低/中/高 → 粗糙/标准/精致 |

#### ③ 页面数据：计分因子

| 因子 | 取值 → 分 |
|------|-----------|
| API 数量档位 | `少量`(0～1)=`0` / `一般`(2～3)=`0.5` / `较多`(4～6)=`1.5` / `极多`(≥7)=`2`；优先 §7 **本页API条数**（须与 §5 一致），否则数 §5 或 PAGE 关联 |
| API 请求编排类型 | `单请求或并行` → `0`；`串行` → `1.0`；`串并行混合` → `1.5`；读 §7；缺 → 记 0 并标 FE 信号不全；旧值 `单请求`/`并行` 按本档计。**门槛**：条数 0～1 只能并行档；=2 禁止混合；混合须 ≥3 且同路径兼有串行依赖与并行扇出（口径同 `lny-prd-page` §7）；条数与编排矛盾 → **信号矛盾** |

> `_shell`/壳层不计。单页 FE 贡献 = ①贡献 + ②贡献 + ③贡献（各维 = 该维因子之和 × 该页迭代系数）。版本 `FE_SP` = §2.1～§2.3 小计之和（= 各纳入页贡献之和）。报告落盘时 **按维分表**，各表明细行 **按小计降序**。

### BE（①～④，与 check 同号；**与 FE 维号独立**）

> **① AD页面规模** = **仅 AD 页**（骨架 + D5 弹窗档 + 本页 API 数量档）；§3.1 **仅页面**。  
> **② 自有API** = 旧 ②～⑤ 合并：按纳入的每个 `API-*` 计一行，**一个维度**。  
> **③ EXT对接** / **④ FEATURE规则** 各自独立明细。  
> **原则**一句；**算法**列只写总公式，分值档与采数细则见下方各维分表。

| 维 | 名称 | 原则 | 算法 |
|:--:|------|------|------|
| ① | AD页面规模 | AD 页壳越非标、弹窗与本页接口越多，后端页侧越重 | （布局基线 + D5 弹窗档 + 本页 API 数量档）× 迭代系数（细则↓） |
| ② | 自有API | 自有接口面越广、读写与联动/特殊通道越重 | （API基线 + 数据操作形态 + 第三方联动 + 特殊通道）× 迭代系数（细则↓） |
| ③ | EXT对接 | 第三方交互越绕、业务越敏感、联调越难，外部集成越重 | （EXT基线 + 交互方向 + 业务敏感度 + 联调门槛）× 迭代系数（细则↓） |
| ④ | FEATURE规则 | 业务分支与验收条款越多，后端规则越重 | （分支数×0.5 + AC条数×0.2）× 迭代系数（细则↓） |

#### ① AD页面规模：计分因子

> **按 AD 页** 一行；行分 =（**布局基线** + **D5 弹窗档** + **本页 API 数量档**）× 迭代系数。骨架码见 `lny-prd-ui` §1.4.1。

| 因子 | 取值 → 分 |
|------|-----------|
| 布局基线 | `D1-2` → `0.8`（表单内容区）；`D1-1` → `1.0`（标准列表壳）；`D0` → `1.5`（空白独立全页）；`D1-3` → `2.0`（自定义内容区）。误写裸 `D1` → 按 `D1-1`；一页多骨架取 **最高** 布局基线。规模直觉：`D1-2` ＜ `D1-1` ＜ `D0` ＜ `D1-3` |
| D5 弹窗档 | 只计 `ui/PAGE-*` **`D5弹窗数`**（与弹窗清单一致；不计 Toast）：`0～2` → `0`；`3～4` → `0.5`；`5～6` → `1.0`；`≥7` → `1.5` |
| 本页 API 数量档 | 去重条数（优先 §7，须=§5）：`0～4` → `0`（含典型增删改查，已由布局 + 维② 覆盖）；`5～6` → `0.5`；`7～9` → `1.0`；`≥10` → `1.5` |

> **采数 / 缺口**：骨架码与 **`D5弹窗数`** ← `ui/PAGE-*`（清单行数须一致）；本页 API ← 优先 §7（须=§5）。缺骨架码或字段不可核 → 该页记 0 并标 BE 信号不全。全量：终端=`AD`；迭代：台账涉及的 AD 页。维 ① 小计 = 各 AD 页贡献之和。

#### ② 自有API：计分因子

> **按 API** 一行；行分 =（**API基线** + **数据操作形态** + **第三方联动** + **特殊通道**）× 迭代系数。  
> **API基线** = 原「计入 + 服务对象」合并（按服务对象一档给基线，不再另加固定 1）。

| 因子 | 取值 → 分 |
|------|-----------|
| API基线 | 读明细 **服务对象**：`前端视图` / `资源管理` → `0.5`；`前端视图和资源管理` → `1`（旧值 `二者` 按全称档） |
| 数据操作形态 | `单对象查询` / `简单写入` → `0`；`多对象关联查询（普通）` / `多对象写入（普通）` → `1`；`多对象关联查询（复杂）` / `多对象写入（复杂）` → `2`。旧值无普通/复杂后缀的 `多对象关联查询` / `多对象写入` → 按 **普通** 计 |
| 第三方联动 | `否` → `0`；`是` → `1`（须挂 `EXT-*`，缺口标 BE 信号不全） |
| 特殊通道 | `否` → `0`；`是` → `1`（WebSocket / SSE / 长连接推送等；产品只标是否，不写协议细节） |

> **范围**：全量 active（或未标废弃）；迭代：台账涉及的 API。维 ② 小计 = 各 API 行小计之和。

#### ③ EXT对接：计分因子

> **按 EXT** 一行；行分 =（**EXT基线** + **交互方向** + **业务敏感度** + **联调门槛**）× 迭代系数。  
> 取代旧单一「对接复杂度」低/中/高；仅有旧字段时：`低→1` / `中→2` / `高→3` 整行计分并标旧值兼容（宜补齐新因子）。

| 因子 | 取值 → 分 |
|------|-----------|
| EXT基线 | 每个纳入的 `EXT-*` 固定 `1` |
| 交互方向 | `单向请求` → `0`；`含异步回调` → `1`；`双向对账或补偿` → `1.5` |
| 业务敏感度 | `普通` → `0`；`交易履约` → `1`；`资金或合规` → `2` |
| 联调门槛 | `文档自测即可` → `0`；`需预约联调` → `1`；`强依赖对方排期或人工` → `3`；`文档未知需研发调研` → `5` |

> **采数**：读 `api/EXT-*.md` 基本信息；缺任一新因子且无旧「对接复杂度」可兼容 → 标 BE 信号不全。维 ③ 小计 = 各 EXT 行小计之和。

#### ④ FEATURE规则：分支与 AC

> 每个纳入的 FEATURE：`(分支数×0.5 + AC条数×0.2)` × 迭代系数。

| 项 | 算法 | 采数 |
|----|------|------|
| 分支数 | × `0.5` | FEATURE 明细中的业务分支个数 |
| AC 条数 | × `0.2` | 验收标准表有效行数 |

> **范围**：active；`draft` 可不计或单列「草稿未估」；`deprecated` 不计。维 ④ 小计 = 各 FEATURE 行小计之和。

版本 `BE_SP` = ① + ② + ③ + ④（**不**乘持久化档）。迭代时：台账涉及对象的贡献先算再乘该行系数。

### 迭代系数（仅「本版变更」模式；连乘）


| 变更形态 | 系数  | 存量数据影响   | 系数  |
| ---- | --- | -------- | --- |
| 新建   | 1.0 | 无        | 1.0 |
| 复制扩展 | 0.4 | 需迁移      | 1.3 |
| 修改   | 0.6 | 需备份或回滚预案 | 1.2 |
| 废弃删除 | 0.5 |          |     |


同一对象多行台账：系数取 **各行连乘结果的最大值**（避免重复惩罚过度；并在报告注明）。

## 门禁

1. **产品链**（STORY→FEATURE→AC→PAGE→API 关键环，同 check §3.1）：不可估 → 仍写 `sp_report.md`，结论「不可估」，**不输出数值合计**。
2. **FE 信号不全**：`FE_SP` 记 `—`，表内列缺口。
3. **BE 信号不全**：`BE_SP` 记 `—`，表内列缺口。
4. 任一侧为 `—` 时，版本「合计」记 `—`（或仅输出有分的一侧并注明）。
