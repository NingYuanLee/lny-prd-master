# 标准工时点权重与报告模板

计算与落盘时 Read 本节。小时口径与校准原理见本节 §0；SP 定义、门禁与校准系数规则见 `lny-prd-sp/SKILL.md`。

## 0. 小时口径与校准

权重版本：`hour-v1`。本表中的 `1 SP = 1 个有效工程小时`，默认假设规格完整、工程和公共组件可用、开发者熟悉项目。计入实现、开发自测、常规联调和常规评审修正；不计等待、需求/设计返工、环境事故及不可预见故障。总点数是总人时，不是日历工期。

所有“纳入”对象均以目标版本 `delivery_scope.md` 中⑧已确认的 `本期开发` Feature 为上限，再沿 Feature 引用取得 PAGE/API/EXT；有变更台账时取该范围与本版变更对象的交集。禁止回退到全部 active 规格。

先按下表计算对象基准点，再乘一个**实现系数**，最后在 FE/BE 汇总处分别乘**团队校准系数**：

`最终侧别 SP = Σ（对象基准点 × 实现系数 × 存量数据影响系数）× 侧别校准系数`

- 无真实工时数据：FE/BE 校准系数均用 `1.0（暂定）`，报告不得写“已校准”。
- 用户直接给出系数：按用户值，并在报告记录来源。
- 用户给出至少 3 个已完成版本的侧别实际小时：先按 `hour-v1` 对每个历史版本重算基准点，再算 `实际小时 ÷ hour-v1 基准点`，取中位数作为该侧系数；FE、BE 分开计算，禁止混成一个系数。禁止直接使用旧权重生成的历史 SP。
- 实际小时必须与本口径范围一致；只有总历时、人员天数但不清楚净投入时，不得反推。

## 1. 权重表（hour-v1 经验基准）

### FE（①～③，与 check 同口径；**纯按页 · 对标 BE**）

> **FE ≠ BE**：FE **三维**，只评 **非 AD** 页（按页计因子；报告 §2.1～§2.3 **分维分表**）。BE 按 AD 页 / API / EXT / FEATURE **分对象四维**估，维号独立。  
> **原则**一句；**算法**列只写总公式，因子细则见下方各维分表。  
> 流程角色表示业务位置，不代表实现工时，**不再参与计分**。每个非 AD 页只计固定实现基线 `0.5`；复杂度由功能、体验与数据因子承担。

| 维 | 名称 | 原则 | 算法 |
|:--:|------|------|------|
| ① | 页面实现 | 每页有固定接线/自测成本，额外功能才增加工时 | （页面实现基线 + 功能数量档）× 实现系数（细则↓） |
| ② | 页面体验 | 交互与视觉越精，前端还原越重 | （交互体验 + 视觉细节）× 实现系数（细则↓） |
| ③ | 页面数据 | 本页接口越多、编排越串，前端对接越重 | （API 数量档 + 请求编排）× 实现系数（细则↓） |

#### ① 页面实现：计分因子

| 因子 | 取值 → 分 |
|------|-----------|
| 页面实现基线 | 每个纳入的非 AD 业务页固定 `0.5`；`_shell`/壳层不计。流程角色不计分 |
| 功能数量档位 | `少量`(0～2)=`0` / `一般`(3～5)=`0.5` / `较多`(6～8)=`1.0` / `极多`(≥9)=`1.5`（按本页 FEATURE 个数）；优先 §6，否则 §7「关联 FEATURE」，再否则 PAGE↔FEATURE 反查；多源不一致 → **信号矛盾** |

#### ② 页面体验：计分因子

| 因子 | 取值 → 分 |
|------|-----------|
| 页面交互体验档位 | `简单` → `0`；`标准` → `0.5`；`较复杂` → `1.0`；`极复杂` → `2.0`；读 `ui/PAGE` 或 manifest；旧值低/中/高 → 简单/标准/较复杂 |
| 页面视觉细节档位 | `粗糙` → `0`；`标准` → `0.5`；`精致` → `1.0`；`极精致` → `1.5`；读 `ui/PAGE` 或 manifest；旧值低/中/高 → 粗糙/标准/精致 |

#### ③ 页面数据：计分因子

| 因子 | 取值 → 分 |
|------|-----------|
| API 数量档位 | `少量`(0～1)=`0` / `一般`(2～3)=`0.5` / `较多`(4～6)=`1.0` / `极多`(≥7)=`1.5`；优先 §7 **本页API条数**（须与 §5 一致），否则数 §5 或 PAGE 关联 |
| API 请求编排类型 | `单请求或并行` → `0`；`串行` → `0.5`；`串并行混合` → `1.0`；读 §7；缺 → 记 0 并标 FE 信号不全；旧值 `单请求`/`并行` 按本档计。**门槛**：条数 0～1 只能并行档；=2 禁止混合；混合须 ≥3 且同路径兼有串行依赖与并行扇出（口径同 `lny-prd-page` §7）；条数与编排矛盾 → **信号矛盾** |

> `_shell`/壳层不计。单页各维贡献 = 该维因子之和 × 对象实现系数 × 存量数据影响系数。版本 `FE_SP` =（§2.1～§2.3 小计之和）× FE 校准系数。报告落盘时按维分表，各表明细行按小计降序。

### BE（①～④，与 check 同号；**与 FE 维号独立**）

> **① AD页面规模** = **仅 AD 页**（骨架 + D5 弹窗档 + 本页 API 数量档）；§3.1 **仅页面**。  
> **② 自有API** = 旧 ②～⑤ 合并：按纳入的每个 `API-*` 计一行，**一个维度**。  
> **③ EXT对接** / **④ FEATURE规则** 各自独立明细。  
> **原则**一句；**算法**列只写总公式，分值档与采数细则见下方各维分表。

| 维 | 名称 | 原则 | 算法 |
|:--:|------|------|------|
| ① | AD页面规模 | AD 页壳越非标、弹窗与本页接口越多，后端页侧越重 | （布局基线 + D5 弹窗档 + 本页 API 数量档）× 实现系数（细则↓） |
| ② | 自有API | 自有接口面越广、数据操作与特殊通道越重；第三方实现只在 EXT 计一次 | （API基线 + 数据操作形态 + 特殊通道）× 实现系数（细则↓） |
| ③ | EXT对接 | 第三方交互越绕、业务越敏感、主动联调/调研越重 | （EXT基线 + 交互方向 + 业务敏感度 + 联调投入）× 实现系数（细则↓） |
| ④ | FEATURE规则 | 只计主路径之外真正增加代码分流的业务分支；AC 行数只用于可评估性 | `max(分支数-1, 0)×0.5×实现系数`（细则↓） |

#### ① AD页面规模：计分因子

> **按 AD 页** 一行；行分 =（**布局基线** + **D5 弹窗档** + **本页 API 数量档**）× 实现系数。骨架码见 `lny-prd-ui` §1.4.1。AD 页归入 BE 是本包“后端/全栈人员承担管理后台”的既有团队口径；若实际由 FE 承担，只调整归属展示，**同一页总点不得重复计算**。

| 因子 | 取值 → 分 |
|------|-----------|
| 布局基线 | `D1-2` / `D1-1` → `0.5`（标准表单/列表壳）；`D0` / `D1-3` → `1.0`（空白独立全页 / 自定义内容区）。误写裸 `D1` → 按 `D1-1`；一页多骨架取 **最高**布局基线 |
| D5 弹窗档 | 只计 `ui/PAGE-*` **`D5弹窗数`**（与弹窗清单一致；不计 Toast）：`0～2` → `0`；`3～4` → `0.5`；`5～6` → `1.0`；`≥7` → `1.5` |
| 本页 API 数量档 | 去重条数（优先 §7，须=§5）：`0～4` → `0`（含典型增删改查，已由布局 + 维② 覆盖）；`5～6` → `0.5`；`7～9` → `1.0`；`≥10` → `1.5` |

> **采数 / 缺口**：骨架码与 **`D5弹窗数`** ← `ui/PAGE-*`（清单行数须一致）；本页 API ← 优先 §7（须=§5）。缺骨架码或字段不可核 → 该页记 0 并标 BE 信号不全。全量：终端=`AD`；迭代：台账涉及的 AD 页。维 ① 小计 = 各 AD 页贡献之和。

#### ② 自有API：计分因子

> **按 API** 一行；行分 =（**API基线** + **数据操作形态** + **特殊通道**）× 实现系数。第三方联动仍是完整性信号，但实现工时统一在维③ EXT 计，禁止 API 与 EXT 双计。
> **API基线**代表单个接口的接线、自测与常规联调，不因同时服务前台和管理端而重复收费。

| 因子 | 取值 → 分 |
|------|-----------|
| API基线 | 纳入的每个 API 固定 `0.5`；服务对象继续展示，但不改变分值 |
| 数据操作形态 | `单对象查询` / `简单写入` → `0`；`多对象关联查询（普通）` / `多对象写入（普通）` → `0.5`；`多对象关联查询（复杂）` / `多对象写入（复杂）` → `1`。旧值无普通/复杂后缀的 `多对象关联查询` / `多对象写入` → 按 **普通** 计 |
| 第三方联动 | `否` → `0`；`是` → `0（转维③ EXT）`（须挂 `EXT-*`，缺口标 BE 信号不全） |
| 特殊通道 | `否` → `0`；`是` → `1`（WebSocket / SSE / 长连接推送等；产品只标是否，不写协议细节） |

> **范围**：已确认 `本期开发` Feature 引用的 API；有台账时再与本版变更 API 取交集。维 ② 小计 = 各 API 行小计之和。

#### ③ EXT对接：计分因子

> **按 EXT** 一行；行分 =（**EXT基线** + **交互方向** + **业务敏感度** + **联调投入**）× 实现系数。联调门槛只代理工程师主动投入，不把等待对方排期的自然时间计为工时。
> 取代旧单一「对接复杂度」低/中/高；仅有旧字段时：`低→0.5` / `中→2.0` / `高→4.0` 整行计分并标旧值兼容（宜补齐新因子）。

| 因子 | 取值 → 分 |
|------|-----------|
| EXT基线 | 每个纳入的 `EXT-*` 固定 `0.5` |
| 交互方向 | `单向请求` → `0`；`含异步回调` → `0.5`；`双向对账或补偿` → `1.0` |
| 业务敏感度 | `普通` → `0`；`交易履约` → `0.5`；`资金或合规` → `1.0` |
| 联调投入（由联调门槛映射） | `文档自测即可` → `0`；`需预约联调` → `0.5`；`强依赖对方排期或人工` → `1.0`；`文档未知需研发调研` → `2.0`。只计准备、沟通、调研和验证的有效投入，不计等待时长 |

> **采数**：读 `api/EXT-*.md` 基本信息；缺任一新因子且无旧「对接复杂度」可兼容 → 标 BE 信号不全。维 ③ 小计 = 各 EXT 行小计之和。

#### ④ FEATURE规则：额外业务分支

> 每个纳入的 FEATURE：`max(分支数-1, 0)×0.5×实现系数`。主路径已经由页面/API 基线覆盖；只有主路径之外会产生代码分流的业务分支加点。AC 行数受文档拆分粒度影响，**不再计分**，但仍须存在并通过产品链门禁。

| 项 | 算法 | 采数 |
|----|------|------|
| 额外分支数 | `max(分支数-1, 0)×0.5` | FEATURE 明细中的业务分支数；首个主路径扣除 |
| AC 条数 | `×0（只审计）` | 验收标准表有效行数；缺失仍按产品链不可估处理 |

> **范围**：`delivery_scope.md` 中已确认的 `本期开发` Feature；`draft` / `deprecated` 不计。维 ④ 小计 = 各 FEATURE 行小计之和。

版本 `BE_SP` =（① + ② + ③ + ④ 的对象小计）× BE 校准系数。存量数据影响只通过下方系数体现，不另设持久化档。

### 实现系数与存量数据影响

每个对象只取 **一个实现系数**，禁止把“复用”“复制扩展”“修改”互相连乘。全量模式和新建对象没有可靠复用证据时用 `1.0`。

| 实现情形 | 实现系数 | 证据要求 |
|----------|---------:|----------|
| 独立新建 | 1.0 | 默认 |
| 复用已落地模板/组件，仍需改业务结构 | 0.6 | 用户明确说明，或规格明确给出实现来源；仅“用了公共组件”不够 |
| 同一套实现跨终端共享，仅做适配 | 0.3 | 用户明确同代码实现及主实现对象；首个主实现仍按 1.0 |
| 台账 `复制扩展` | 0.4 | 读台账变更形态 |
| 台账 `修改` | 0.6 | 读台账变更形态 |
| 台账 `废弃删除` | 0.5 | 读台账变更形态 |

| 存量数据影响 | 系数 |
|--------------|-----:|
| 无 | 1.0 |
| 需迁移 | 1.3 |
| 需备份或回滚预案 | 1.2 |

对象小计 = 对象基准点 × 实现系数 × 存量数据影响系数。同一对象多行台账时，取各行结果的最大值，避免重复计价；报告必须注明复用来源和系数证据。不得仅因页面名称相似、同属一个终端或 Agent 猜测可复用而折减。

## 门禁

1. **产品链**（规格承载；STORY→FEATURE→AC→PAGE/API/EXT，FEATURE→MODULE，同 check §3.1）：不可估 → 仍写 `sp_report.md`，结论「不可估」，**不输出数值合计**。
2. **FE 信号不全**：`FE_SP` 记 `—`，表内列缺口。
3. **BE 信号不全**：`BE_SP` 记 `—`，表内列缺口。
4. 任一侧为 `—` 时，版本「合计」记 `—`（或仅输出有分的一侧并注明）。

## `sp_report.md` 模板

> 落盘 **仅** 本模板结构；数值保留 **1 位小数**。单元格写 **得分**（必要时括号附枚举，如 `0.5（一般）`）。没有复用/迭代折减时「实现系数」填 `1.0`。不可估时仍落盘，**§1 合计与明细数值用 `—`**，§5 写明断点。
> **小计纪律**：§2.1～§2.3、§3.1～§3.4 **每一明细表末**必须有表内 **`小计（…）` 汇总行**（加粗）及一行说明；§1、§2.4、§3.5 用加粗汇总表，数字醒目。  
> **排序纪律**：§2.1～§2.3、§3.1～§3.4 **每一明细表**的数据行按 **小计降序**（同分则按编号升序）；小计汇总行始终在表底。

## 3. BE 明细

### 3.1 AD页面规模（维① · 仅 PAGE）
