### 1.1 版本号与变更记录

- **v1.0.0**：仅立项创建目录与各规范变更记录首行。续跑与 ②～⑨ 不得再建/再写该行。⑧ 不得补初始化 v1.0.0。
- **新版本行**：仅 ⑧ 可新建 `versions/{新版本号}/` 并追加一行。细则见 `lny-prd-iter`。
- **其余技能**：不得在变更记录表新增行；同版本不得多行（发现则交 ⑦/⑧，他步不擅自改表）；表内版本须与 `versions/` 文件夹一致；「文档版本」只能填已存在的版本目录。
- **过程流水**：②③④⑤ 改根四规范（`main_spec` / `api_spec` / `ui_manifest` / `feature_spec`）正文时，在当前版本 `iteration_notes.md` 文末追加一条业务摘要。⑥ 不改根规格与流水（可覆盖刷新 `prototypes/index.html`）；⑦ 只读；⑨ 只写 `sp_report.md`（总入口由同轮 **§3.3** 刷）。⑧ 写开篇；其后仍可文末追加，不替代变更记录新行。
- **当前工作版本**：未指定则取 `versions/` 最大 semver；用户显式版本优先且目录须已存在；与文档头不一致时以 `versions/` 为准。

### 3.1 规格三件套批（②③④ 并行，禁止拆「继续」）

> **问题**：§3 的 B→C→D 优先级 +「每轮只做一步」会把本可并行的 ②③④ 拆成三次「要不要继续」。

**何时触发批跑（满足其一）**：

1. **续跑 / 立项后首次补规格**：同时检测 B、C、D 条件；凡未满足的，**本轮全部执行**（顺序建议：先 **② ui** 定 PAGE，再 **③ api** 与 **④ feature** 可紧接着同一轮完成；三者都缺时 **②→③→④ 连续落盘**，中间 **禁止** 停下来问用户「继续」）。
2. **I2-spec 委派**：台账同时存在 `待②` / `待③` / `待④`（或任两两组合）时，**同轮清完**所有 ②③④ 待办后再结束本轮；**不要** 做完 ② 就停。`待⑤` 不进本批，由 **I2-page** 执行；若本轮同时是演示目标，I2-page 之后继续 ⑥。
3. 用户消息明确写「并行 / 一次做完规格三件套 / 一起补 ui api feature」→ 强制本批。

**批内纪律**：

- 开批时明示：`本轮规格三件套批：②… ③… ④…`（列出实际要做的子集）。
- 每步仍须 **完整 Read** 对应 `SKILL.md` 再落盘；遵守各步写产物纪律与框架排除。
- 批结束后 **只问一次** 下一步（通常 **⑤** 或「继续」进总控），**禁止** 在 ② 与 ③、③ 与 ④ 之间索要确认。
- 若某步因缺用户输入无法落盘：列出缺口，**其余可做的 ②③④ 仍做完**，再停；不要因 ③ 缺字段而整批不做。

**仍须单步（不进本批）**：⑦ check、⑧ iter、⑨ sp、以及 B2 改终端表。⑤⑥ 仅在用户目标为原型时进 **§3.2**，不进本三件套批。⑨ 的总入口刷新属 **§3.3**，含在 H2 同一轮，不另要「继续」。

**「继续」**：用户回复「继续」时 **重新执行 §3**。命中 **§3.1 批**（未清 ②③④ 或规格缺口）则本轮批跑；命中 **G-partial**（缺业务 `PAGE-*.html`）则本轮只 ⑥ 续批；命中 **§3.2** 仅当当轮仍是演示/原型目标。规格已齐、原型页已齐且无未清 I2 时命中 **J**：**只建议** ⑤⑥⑦⑨，**不**自动落盘。**例外**：上一轮是 **H2**「是否补规格再估」的询问时，本轮回执仍走 **H2**（肯定 → §3.1 再 ⑨；否定 → 只 ⑨ 写 `—`），**不**落到 B/C/D。**不**要求用户自选子指令。

### 3.2 目标驱动补链（静默 ②→⑥，禁止静默 ⑧）

用户目标是原型 / 演示 / 给老板看 / 先出个页面（而非「只要规格」）时：**交付物是原型**。规格或 `pages_prd` 缺口则本轮补齐再出原型；不要拒绝跳步，不要问「要不要先写规格」。

**不得压过**：未清 I2 委派、明确要求的 ⑦ 检查 / ⑨ 估点 / ⑧ 新迭代。演示措辞不能把「检查」做成刷原型，也不能静默开版本。

- **本轮可连续**：缺则做 ②③④（可走 §3.1）→ ⑤ → ⑥。每步仍须完整 Read 对应 `SKILL.md`。⑥ 被直接唤起且发现缺口时，**⑥ 内接着补 ②③④⑤ 再写 HTML**，禁止停下来只说「交总控」。结束时列出自动补了哪些步。
- **⑥ 分批**：每轮最多 **3** 个业务 `PAGE-*.html`；写每一页前必须 Read 该页 `pages_prd`（及 `ui/PAGE`、引用 COMP）。禁止同轮把全部页画完。未完成则列出剩余编号；下一轮「继续」走 **G-partial** 只续 ⑥，禁止重做规格。壳层 `index`/`map`/总入口每批末只挂已落盘页。
- **只问产品事实**：终端有哪些、首页有什么等。不问流程问题。
- **落在当前版本**：未指定则取 `versions/` 最大 semver。改文案、补页、出原型一律不新建版本目录。
- **禁止静默 ⑧**：只有用户明确「新迭代 / 新版本 / `/lny-prd-iter`」才走 I。对话不主动推销开版本。小改（如首页改两字）走当前版本 ②⑤⑥，不为此建 v1.1.0。
- **不进本批**：⑦⑨⑧（检查/估点仍须用户明确要求）。

### 3.3 估点后刷总入口（⑨→⑥ 只刷，禁止重画页面）

⑨ 覆盖写入 `sp_report.md` 之后（含不可估 / `—`），**同一轮** Read `lny-prd-prototype/SKILL.md` 的「只刷总入口」：只覆盖 `prototypes/index.html` 与 `versions/{v}/prototypes/index.html`。

- **禁止**：copy-kit；改各端 `PAGE-*.html`、端 `index.html`、`map.html`；把估点目标升级成 §3.2 全量出原型。
- **跳过**：尚无任何 `prototypes/{终端}/` 时不新建空总入口，对话说明「无原型可挂」。
- **直接唤起** `/lny-prd-sp` 时由 ⑨ 技能内执行本段，**禁止**停下来只说「交总控」。
- 这不是静默 ⑥ 全量，也不是 ⑨ 手改 HTML。

### 4. 防碎片化（总控层要求）

- 进入子步后，遵守该步 `SKILL.md` 中的 **写产物纪律**（先读全篇或全章、变更清单、整块落盘）。
- 同一轮对话：默认完成 **一个** 判定步骤；**例外**为 **§3.1 规格三件套批**、**§3.2 目标驱动补链（可 ②→⑥，其中 ⑥ 每轮最多 3 个业务页）**、**§3.3 估点后只刷总入口**、**G-partial 续批 ⑥**。结束时报：**已执行步（可多项）**、**下一步建议**、**将 Read 的 SKILL 路径**。

# 立项 `/lny-prd-master`

## 功能

创建项目初始文档和文件夹结构，第一个版本在 `versions/v1.0.0/` 下。

> **版本纪律**：仅立项可初始化 `v1.0.0` 与变更记录首行；更高版本与变更记录新行仅 ⑧。其他技能不得在变更记录表新增行；根规格留痕只写当前版本 `iteration_notes.md` 文末，见 **§1.1**。

## 输入方式

仅支持 **一次性输入** 与 **Agent 对话式补充**。

### 一次性输入（推荐）

同一条消息附 YAML。完整字段见 [`reference-init.md`](reference-init.md)。最少：项目名称、定位、用户与故事、产品目标、终端范围；可选 `框架排除 profile`（`lny-default` / `none`）、`框架内置排除`、`成功怎么算`、`明确不做`。

### 对话式补充

仅发 `/lny-prd-master` 或未带齐字段时，用自然语言补立项要素，可少量来回；齐后输出确认摘要，用户回复「确认」再落盘。**禁止**选择框/多选框分步表单。

> 小程序分包、页面架构与 `ui_manifest.md` 由 **②** 补充。

## 信息确认

```
📋 项目立项信息确认：
- 项目名称：xxx
- 产品定位：xxx
- 目标用户和故事：
  1. {用户A}：{故事A}
  2. {用户B}：{故事B}
- 产品目标：xxx
- 终端范围：小程序、管理后台
- 成功怎么算：{1～3 句；未填则「未填写」}
- 明确不做：{列表；未填则「未声明」}
- 竞品参考：xxx
- 术语介绍：xxx
- 框架排除 profile：lny-default（个性化配置，不是强制行业表；或 none）
- 框架内置排除（默认排除）：Read [`framework-exclusions.md`](framework-exclusions.md)
- 本项目追加排除（如有）：{用户 YAML 或口头补充}

确认无误请回复"确认"；如需增减排除项请说明。不沿用默认表 → `none` 或把排除表拷到 PRD 根后自行改。
```

`lny-default` 是作者栈的个性化 profile，**不是**强制行业表。立项须确认是否沿用；**未确认不得按默认表删需求**。用户提到的能力（登录、支付等）若与排除清单冲突，二次确认。

②③④⑤⑥ **禁止**展开「明确不做」；⑦ 用「成功怎么算 / 明确不做」做规格外与主路径。不填则不拿「该不该做」压人。为过检查去改「明确不做」列表属越权（除非用户明确要求改范围）。

埋点：仅当 PM 已说出点位或 AD 字典条目才落规格或原型；**禁止自拟埋点方案**。RBAC 维持排除，不写权限矩阵。

## 执行步骤

1. 创建空目录：`api/`、`ui/`、`feature/`（新立项只走目录化）
2. 生成根规范（**不在项目内落地 `.templates/`**）：
   - `main_spec.md` ← [`reference-init.md`](reference-init.md)
   - `api_spec.md` ← `lny-prd-api/reference.md`
   - `ui_manifest.md` ← `lny-prd-ui/reference.md`
   - `feature_spec.md` ← `lny-prd-feature/reference.md`
3. 四份文档统一文档信息 / 变更记录首行 v1.0.0；`main_spec` 第4章终端表直接放在二级标题下，**禁止** `###` 小节
4. 创建 `versions/v1.0.0/` 与 `iteration_notes.md`（含「版本名称」，无则写「首版」）
5. 输出结构；下一步总控进规格三件套（②③④ 可并行）

## 续跑：新增/变更/删减终端

仅当用户明确要求或 §3 命中 **B2**；② 不得代改第4章。

1. 确认终端名称、类型编码、描述
2. 更新 `main_spec.md` `## 4. 终端说明` 下表格（禁止 `### 4.x`）
3. 同步 §5 / §6 汇总行（数量由后续 ② 补齐）
4. `iteration_notes.md` 文末追加流水
5. 下一步 ② 补 `ui_manifest` §2 及该终端页面
