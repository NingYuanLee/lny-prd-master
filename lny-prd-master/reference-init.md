# 立项模板

立项 YAML 与 `main_spec.md` 骨架。立项时 Read 本节落盘；**不在项目内落地 `.templates/`**。

## 立项 YAML

```yaml
项目名称:
产品定位:
目标用户和故事:
  - 用户: {用户A描述}
    故事: {故事A描述}
产品目标:
终端范围: [小程序, App, 管理后台]
竞品参考: (可选)
专业术语介绍: (可选)
框架排除 profile: lny-default   # 个性化配置，不是强制；或 none
框架内置排除: []   # 在默认排除之上的本项目追加项
成功怎么算:    # 可选，1～3 句
明确不做: []   # 可选
```

## 首版 `delivery_scope.md` 模板

立项只创建阻塞壳，不替产品做批准决定。②③④ 补齐后，由产品明确本期 Feature 与评审结论。

```markdown
# 交付范围 - v1.0.0

## 1. 范围状态

> **产品经理填写说明**
> - `评审状态` 只填一个值：尚未发起评审填 `pending`；正在评审填 `reviewing`；存在阻塞、暂不能确认范围填 `blocked`；本期范围已明确且不存在未关闭问题时填 `approved`。
> - `产品确认项` 填仍未关闭且影响本期范围确认的问题数量。每关闭一项同步递减，全部关闭后改为 `0`。
> - 推荐流转：`pending` -> `reviewing` -> `approved`；评审中发现阻塞时改为 `blocked`，解除阻塞后回到 `reviewing`，重新确认后再改为 `approved`。

| 属性 | 内容 |
|------|------|
| 版本号 | v1.0.0 |
| 评审状态 | pending |
| 产品确认项 | {非负整数；未完成范围确认时至少为 1} |

## 2. Feature 范围

> **产品经理填写说明**
> - `Feature` 填根 `feature_spec.md` 中已登记的 `FEATURE-###`；尚未确定时保留阻塞壳，不能从全部 `active` Feature 自动推断。
> - `纳入方式`：确定本期实现时填 `本期开发`；迭代中明确废弃并需要同步关闭外部研发工作项时填 `本期下线`；尚未确定时填 `待确认`；其余 Feature 不保留在本表中。
> - 生命周期必须匹配：`本期开发` 对应 Feature `状态=active`，`本期下线` 对应 `状态=deprecated`；废弃只改状态并保留历史明细文件。
> - 行级 `评审状态` 与范围级使用同一组状态，但表示该 Feature 的开发或下线结论是否已经确认；只有已确认的本期 Feature 才改为 `approved`。
> - `阻塞决策` 填下方仍为 `open` 且影响该 Feature 的决策数量；相关决策关闭后同步递减，全部关闭后改为 `0`。

| Feature | 纳入方式 | 评审状态 | 阻塞决策 |
|---------|----------|----------|----------|
| 无 | 待确认 | pending | {非负整数；未完成范围确认时至少为 1} |

## 3. 未决决策

> **产品经理填写说明**
> - 每个待确认问题单独一行：未形成结论填 `open`，形成明确结论并已同步相关 PRD 后改为 `closed`。
> - `影响对象` 填受影响的 `FEATURE-###`；影响多个 Feature 时用逗号分隔。没有未决问题时仅保留 `| 无 | closed | 无 | 无 |`。
> - 所有决策均为 `closed` 后，才可把上方对应的 `阻塞决策` 归零；其他门禁也满足后，再将评审状态改为 `approved`。

| 决策编号 | 状态 | 问题 | 影响对象 |
|----------|------|------|----------|
| DECISION-001 | open | 明确本期开发 Feature | 待确认 |
```

| STORY-002 | {用户B} | {用户B画像描述} | {故事B} | {FEATURE-002} |

{竞品分析内容}

### 1.5 明确不做（可选）
- {未声明则写「未声明」}

## 2. 通用规范
### 2.1 编号规则说明
**终端类型编码说明：**
| 终端类型 | 终端类型编码 | 说明 |
|----------|--------------|------|
| 微信小程序 | MP | Mini Program |
| App | APP | Application |
| H5网页 | H5 | H5 Web |
| PC网页 | PC | PC Web |
| 管理后台 | AD | Admin |

**页面编号规则：** `PAGE-{终端类型编码}-{三位序号}`
- 示例：PAGE-MP-001、PAGE-APP-002、PAGE-H5-003、PAGE-PC-004、PAGE-AD-005

**接口编号规则：** `API-{终端类型编码}-{三位序号}`
- 示例：API-MP-001、API-APP-002、API-H5-003、API-PC-004、API-AD-005

**第三方接口编号规则：** `EXT-{三位序号}`
- 示例：EXT-001、EXT-002、EXT-003

**组件编号规则：** `COMP-{三位序号}`
- 示例：COMP-001、COMP-002、COMP-003

**功能编号规则：** `FEATURE-{三位序号}`
- 示例：FEATURE-001、FEATURE-002、FEATURE-003

**业务模块编号规则：** `MODULE-{三位序号}`
- 示例：MODULE-001、MODULE-002；模块改名时编号不变，不使用云效实际 ID

**用户故事编号规则：** `STORY-{三位序号}`
- 示例：STORY-001、STORY-002；与 FEATURE 可为 N:M（FEATURE 明细标明主/次关联）

**文件路径模板：**
- 小程序主包：`pages/{模块名}`（首页模块 **必须为 `index`**，路由 `pages/index/index`；**禁止** `home`）
- 小程序分包：`subpackages/{模块名}`
- 小程序完整路由：`{路径前缀}/{页面文件名}`（见 `lny-prd-ui` 路由规范）
- 管理后台：`views/{模块名}`

### 2.2 文件命名规则
- 页面PRD文档：`{页面编号}.md`（如 `PAGE-MP-001.md`）
- 页面原型文件：`{页面编号}.html`（如 `PAGE-MP-001.html`）
