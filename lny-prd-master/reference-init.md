# 立项模板

立项 YAML 与 `main_spec.md` 骨架。立项时 Read 本节落盘；**不在项目内落地 `.templates/`**。

## 立项 YAML

```yaml
项目名称:
产品定位:
目标用户和故事:
  - 用户: {用户A描述}
    故事: {故事A描述}
产品目标:
终端范围: [小程序, App, 管理后台]
竞品参考: (可选)
专业术语介绍: (可选)
框架排除 profile: lny-default   # 个性化配置，不是强制；或 none
框架内置排除: []   # 在默认排除之上的本项目追加项
成功怎么算:    # 可选，1～3 句
明确不做: []   # 可选
```

## 2. 通用规范
### 2.1 编号规则说明
**终端类型编码说明：**
| 终端类型 | 终端类型编码 | 说明 |
|----------|--------------|------|
| 微信小程序 | MP | Mini Program |
| App | APP | Application |
| H5网页 | H5 | H5 Web |
| PC网页 | PC | PC Web |
| 管理后台 | AD | Admin |

**页面编号规则：** `PAGE-{终端类型编码}-{三位序号}`
- 示例：PAGE-MP-001、PAGE-APP-002、PAGE-H5-003、PAGE-PC-004、PAGE-AD-005

**接口编号规则：** `API-{终端类型编码}-{三位序号}`
- 示例：API-MP-001、API-APP-002、API-H5-003、API-PC-004、API-AD-005

**第三方接口编号规则：** `EXT-{三位序号}`
- 示例：EXT-001、EXT-002、EXT-003

**组件编号规则：** `COMP-{三位序号}`
- 示例：COMP-001、COMP-002、COMP-003

**功能编号规则：** `FEATURE-{三位序号}`
- 示例：FEATURE-001、FEATURE-002、FEATURE-003

**用户故事编号规则：** `STORY-{三位序号}`
- 示例：STORY-001、STORY-002；与 FEATURE 可为 N:M（FEATURE 明细标明主/次关联）

**文件路径模板：**
- 小程序主包：`pages/{模块名}`（首页模块 **必须为 `index`**，路由 `pages/index/index`；**禁止** `home`）
- 小程序分包：`subpackages/{模块名}`
- 小程序完整路由：`{路径前缀}/{页面文件名}`（见 `lny-prd-ui` 路由规范）
- 管理后台：`views/{模块名}`

### 2.2 文件命名规则
- 页面PRD文档：`{页面编号}.md`（如 `PAGE-MP-001.md`）
- 页面原型文件：`{页面编号}.html`（如 `PAGE-MP-001.html`）
