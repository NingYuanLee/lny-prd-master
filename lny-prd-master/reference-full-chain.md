# LNY-PRD 完整链模式

默认按请求执行。原型目标自动推进到原型完成。用户明确要求“完整做完”“直接出可评审原型”“自动推进”或“自动检查”时，启用本文件的完整链。

## 规格链

缺少规格时按 `② UI → ③ API → ④ Feature → ⑤ Page → Q-S` 执行。②先锁定 PAGE/COMP，③和④只有输入充分且互不依赖时才并行。Q-S 失败时回到最早责任步骤修复。

## 原型链

原型目标且规格链已齐时自动执行 `⑥ Prototype`。原型目标缺少前置规格时先补规格链。⑥完成后提示用户是否执行 Q-P。用户明确要求检查或已选择执行时才运行 Q-P。Q-P 的实现问题回⑥，规格问题回责任步骤并重跑 Q-S。

## 评审与返修

Q-P 通过后停止并询问是否进入⑧，除非用户已经明确要求评审。⑧的调整、附条件通过或退回结论按影响范围回到②～⑤、Q-S、⑥、Q-P，再回到⑧。未经用户确认不得发布批准快照。若用户不执行 Q-P，则停在“原型已完成，Q-P 待用户决定”。

## 估点与迭代

⑨写入 `sp_report.md` 后只刷新 `prototypes/index.html`，不重画页面。⑩只在用户明确要求新迭代或新版本时创建版本目录。

## 并行

仅在至少两个边界清晰、互不依赖且有独占输出的任务时并行。先锁定 ID、依赖和写路径，再按波次 fan-out/fan-in。没有并行能力时顺序执行。
