# 框架内置能力（不纳入 PRD）

**profile = lny-default**（ThinkPHP / uni-app / 微信支付 / 类 likeadmin）。这是作者栈的**个性化配置**，不是强制行业表。

立项确认时显式展示 profile 询问；**用户未主动要求更改即按默认沿用**。不沿用 → YAML 声明 `框架排除 profile: none`，或把本文件复制到 PRD 项目根覆盖。**立项确认完成前不得按本表删需求。看不见下方闭集清单，不得请用户确认。**

### 确认摘要必列类别（闭集）

`lny-default` 确认摘要必须**逐条写出**下列类别，禁止只写「见本文件」或「默认排除」。细则仍在后文表格，对话里不要贴整表。`none` 时改写「无默认排除，仅遵守本项目追加项」。

1. 登录/鉴权
2. RBAC/后台基础管理
3. 上传/资源
4. 支付/充值提现
5. 微信与小程序通道
6. 通知
7. 队列/WebSocket
8. 系统配置与字典
9. uni-app 请求与 TabBar 底座

- 换栈：立项 YAML 声明 `框架排除 profile: none`（空表，全部业务能力都可建 PAGE/API/FEATURE），或把本文件复制到 PRD 项目根覆盖。
- **profile `none`**：不采用下表默认排除；仅遵守用户追加的 `框架内置排除`。
- **合并规则**：所选 profile 默认排除 ∪ 立项 YAML「框架内置排除」∪ 用户最新确认。
- **②③④⑤⑥⑦⑧ 开笔前必须 Read 本文件**；子技能禁止再枚举具体能力名。
- 命中排除表时，PRD 只写「沿用框架能力 / 按框架约定配置 / 复用现有接口」；只写新增业务规则、字段口径、流程/权限/页面/状态差异。确需改底层能力时，先建立技术使能 Story，再把可交付改造建成 Feature；不得以「框架调整」代替需求来源。

### 仍须写 PRD 的边界

- **业务页内** 展示用户信息 → 可保留对应 `PAGE-*` + **读**接口 + 精简 Feature（**不含**鉴权/登录流程正文）。
- **业务接口** 鉴权 → `api_spec` **§1 PRD 边界** 可写 **「由公司统一框架鉴权」** 一句，**不** 展开登录接口字段。
- **支付、第三方票务** 等业务 **`EXT-*`** → **仍须**编写；PRD **只写**与本项目相关的 **业务差异**（场景、状态、校验、字段口径），**不**重写通道/SDK 通用流程。
- **业务 `API-*` / `FEATURE-*`** → 订单、列表、业务配置、含支付/通知 **业务分支** 的流程等 **照常**编号；**不**为「用户登录」「静默登录」「通用上传接口」等 **框架通用** 能力单独建档。
- **新增业务配置项 / 字典项 / 开关** → 在业务规格中 **只列新增项** 及口径，**不**重写系统配置模块本身。
- **TabBar / 路由**：`ui_manifest` §3.1.1 登记 **业务 Tab 页** 与 `pagePath`，§3.2 登记页面实际地址；这些属于差异配置，不表示用户路径或业务跳转规则，也不与「不展开 tabbar 实现」冲突。
- **上传 / 富文本 / 列表组件**：业务表单 **使用** 框架能力时，只写 **字段、校验、展示口径** 或表内 **特殊约束**，**不**重写组件/请求层实现。

### 排除口径（与子技能对齐，避免误读）

**「不为已排除项建 PAGE/API/FEATURE/EXT」** 指 **框架通用能力本身**（登录页、管理员 CRUD、通用上传服务、RBAC 配置页、微信 OAuth 通用接入说明等），**不**禁止业务侧 **引用** 这些能力。

| 场景 | 是否建规格 | 写法 |
|------|------------|------|
| AD 登录 / MP 静默登录 / 改密 | **否** | 不写 PAGE/API/FEATURE |
| 业务首页、列表、下单 | **是** | 正常 `PAGE-*` + `API-*` + `FEATURE-*` |
| 个人中心 / mine Tab **仅有框架默认空壳** | **否** | 不写 PAGE |
| mine Tab **含业务模块**（订单、会员卡等） | **是** | 建 `PAGE-*`，**只写业务分区** |
| 业务支付（下单唤起支付、失败重试） | **是** | `FEATURE-*` + 业务 `API-*`；支付 **通道** 写「沿用框架能力」 |
| 票务 / 第三方业务 `EXT-*` | **是** | `EXT-*` **只写业务差异** |
| 表单里用框架 upload / mp-html | **是** | 只写字段与 **特殊约束**，不写上传 SDK |

**与子技能冲突时**：以 **本节 + 「仍须写 PRD 的边界」** 为准。

### 本项目追加排除（立项 / 续跑）

- 立项 YAML 可用 **`框架内置排除`** 列出 **在默认排除之上** 的本项目项。
- 可选：在 `main_spec.md` 或 `versions/{版本号}/iteration_notes.md` 记一笔 **本项目排除摘要**（**非**立项模板强制章节）。
- **合并规则**：`lny-default`（若未选 `none`）∪ 立项 YAML「框架内置排除」∪ 用户最新确认。`none` 时下表不生效。

### 各步执行要求（子技能照此执行，勿另写死清单）

| 步骤 | 要求 |
|------|------|
| ① master | 维护本节；立项确认摘要必须列出「确认摘要必列类别」（`none` 则写无默认排除）；看不见清单不得请用户确认 |
| ② ui | 不为已排除项建 `ui/PAGE-*` / `ui_manifest` 索引行；命中上表 **只写差异**，**不**展开框架实现 |
| ③ api | 不为 **框架通用** 已排除项建 `api/API-*` / `api/EXT-*`；**业务** API/EXT（见「仍须写 PRD 的边界」）**仍须**建档且 **只写差异** |
| ④ feature | 不为 **框架通用** 已排除项建 Feature；**业务** 流程 Feature（含支付/通知 **业务分支**）**仍须**编写且 **只写差异** |
| ⑤ page | 不为已排除项生成 `pages_prd` |
| ⑥ prototype | 不生成已排除项对应 `PAGE-*.html` |
| ⑦ check | 若规格与 **本节 + 本项目追加** 重复展开框架能力 → 🔴 阻塞 |
| ⑧ review | 不把框架内置能力当作本期候选价值或独立交付范围；只评审业务差异与明确框架调整 |
