# 总控状态检测路由

① 命中 [`SKILL.md`](SKILL.md) §3 短树后 **Read 本文件对应条再执行**。优先级从高到低，命中即停。条件以 PRD 根实际文件为准，勿凭猜。§3.1 / §3.2 / §3.3 执行协议仍在 SKILL，不在本表重复。

⑦保留编号但作为横向门禁：⑤后自动Q-S，⑥作者自检后自动Q-P。`NEXT_STEP_ROUTE:` 作为自动返修信号；缺产品事实时才停下询问。

## 优先级表

| 顺序 | 条件（简化表述；以实际文件为准） | 执行 |
| --- | --- | --- |
| A | 尚无 `main_spec.md` 且目录无非隐藏文件、正走 **SKILL §2** 立项 | 仅执行 SKILL **立项**；完成后生成 `main_spec.md` 等 |
| B2 | 用户明确要求**新增/变更/删减终端**，或 `ui_manifest`/`api_spec` 所需终端不在 `main_spec` 第4章表中 | **① master**：Read SKILL，更新 `main_spec` **第4章终端说明**（**无** `###` 小节）；再交 **②** 补 `ui_manifest` |
| Review | 用户明确要求需求/产品/范围评审，或处理上一轮⑧结论；同时明确新版本时除外 | 若无本轮有效Q-S/Q-P，先自动补完整链到Q-P。首版读根完整规格；非首版读当前三类change、根当前事实与上一版批准基线。执行PAGE版本范围原子性门禁；冲突则调整范围或按SKILL §3.4回②③④，禁止靠裁剪快照通过 |
| Review-rework | 已确认⑧阶段结论仍为 `reviewing/blocked`，且存在明确返修动作 | 按影响对象从最早责任步骤②/③/④开始，自动⑤→Q-S→⑥→Q-P，再回⑧；已有HTML也按影响重画，不以“文件存在”判完成 |
| I2-spec | `versions/{latest}/` 存在且台账仍有 `待②` / `待③` / `待④` | 见SKILL §3.1清完②③④，然后自动⑤→Q-S→⑥→Q-P；明确只要规格则停在Q-S |
| I2-page | 无 `待②`/`待③`/`待④`，但台账仍有 `待⑤` | ⑤完成后自动Q-S→⑥→Q-P；明确只要规格则停在Q-S |
| H | 用户明确检查 | “检查规格”→⑦/Q-S；“检查原型/能不能演示”→⑦/Q-P（无有效Q-S则先跑）；未限定→⑦/full |
| H2 | 用户明确要求估点 / 故事点 / SP / `/lny-prd-sp`（**估点**优先于演示措辞）；**或**上一轮因规格不齐询问是否补规格再估、本轮给出回执 | **⑨**：先要求目标版本已有 ⑧ 确认范围；无确认范围则建议先 ⑦/⑧，不对全部 active Feature 猜范围。范围已确认但规格不齐且尚未问 → **先问**。**肯定**（是 / 好 / 补 / 补完再估 / 仅当上一轮是本问时的「继续」）→ 先 §3.1 再 ⑨。**否定**（否 / 不补 / 只估现有）→ 只跑 ⑨（不可估则按门禁写 `—`，**不**补规格）。⑨ 落盘后同一轮 **§3.3** 只刷总入口，禁止拆成两次「继续」，禁止因此重画各端页面 |
| I | 用户明确要求新迭代 / 新版本 / `/lny-prd-iter` | **⑩ iter**：Read `lny-prd-iter/SKILL.md`；先只读核验当前最新版本的 ⑧ 评审终态、应有的 ⑨ SP 与未清台账，未闭合则停止建版并建议对应责任步；**禁止**被演示措辞改成静默 ⑩ |

| J | 无上述命中且Q-S/Q-P已通过 | 输出“已具备⑧评审条件”并询问是否进入⑧；若已有⑧终态，则按结论建议⑨或等待明确⑩ |

**自动化边界**：⑤、Q-S、⑥、Q-P不逐步索要“继续”；缺产品事实或准备进入⑧时才询问。禁止用HTML代替规格，禁止静默⑩。
