# 总控状态检测路由

① 命中 [`SKILL.md`](SKILL.md) §3 短树后 **Read 本文件对应条再执行**。优先级从高到低，命中即停。条件以 PRD 根实际文件为准，勿凭猜。§3.1 / §3.2 / §3.3 执行协议仍在 SKILL，不在本表重复。

当本轮消费 ⑦ 检查输出时，其 `NEXT_STEP_ROUTE:` 名单作为**委派建议信号**优先参考（`none` 表示无待办委派），不得反压用户明示的检查/评审/估点/迭代要求。

## 优先级表

| 顺序 | 条件（简化表述；以实际文件为准） | 执行 |
| --- | --- | --- |
| A | 尚无 `main_spec.md` 且目录无非隐藏文件、正走 **SKILL §2** 立项 | 仅执行 SKILL **立项**；完成后生成 `main_spec.md` 等 |
| B2 | 用户明确要求**新增/变更/删减终端**，或 `ui_manifest`/`api_spec` 所需终端不在 `main_spec` 第4章表中 | **① master**：Read SKILL，更新 `main_spec` **第4章终端说明**（**无** `###` 小节）；再交 **②** 补 `ui_manifest` |
| Review | 用户明确要求需求/产品/范围评审、判断是否值得做，或维护既有版本的本期开发/下线范围与未决决策；**或上一轮 ⑧ 结论包待处理且本轮确认、否定、补充或调整**；同时明确新迭代/新版本时除外 | **⑧ review**：Read `lny-prd-review/SKILL.md`；首次评审若无本轮有效 ⑦ 结果，先同轮 Read 并执行 `lny-prd-check/SKILL.md` 的只读检查，再由 ⑧ 主动组装候选范围并给唯一拟定结论包；调整轮重评并重发完整结论，确认轮创建或更新 `delivery_scope.md`，并按需同轮交 ④ 同步 Feature 评审状态 |
| I2-spec | `versions/{latest}/` 存在且 `ui_changes.md` / `api_changes.md` / `feature_changes.md` 中仍有 `待②` / `待③` / `待④`（**⑩ 已建版、规格委派未清**） | 见 SKILL **§3.1** 清完 ②③④。若本轮**同时**是演示/原型目标，清完后**同一轮**继续 §3.2 的 ⑤⑥ |
| I2-page | 无 `待②`/`待③`/`待④`，但台账仍有 `待⑤` | **⑤ page**。若本轮**同时**是演示/原型目标，⑤ 完成后**同一轮**继续 ⑥ |
| H | 用户明确要求检查（含「检查能不能演示」等：**检查**优先于演示措辞） | **⑦ check**：Read `lny-prd-check/SKILL.md`（只读报告） |
| H2 | 用户明确要求估点 / 故事点 / SP / `/lny-prd-sp`（**估点**优先于演示措辞）；**或**上一轮因规格不齐询问是否补规格再估、本轮给出回执 | **⑨**：先要求目标版本已有 ⑧ 确认范围；无确认范围则建议先 ⑦/⑧，不对全部 active Feature 猜范围。范围已确认但规格不齐且尚未问 → **先问**。**肯定**（是 / 好 / 补 / 补完再估 / 仅当上一轮是本问时的「继续」）→ 先 §3.1 再 ⑨。**否定**（否 / 不补 / 只估现有）→ 只跑 ⑨（不可估则按门禁写 `—`，**不**补规格）。⑨ 落盘后同一轮 **§3.3** 只刷总入口，禁止拆成两次「继续」，禁止因此重画各端页面 |
| I | 用户明确要求新迭代 / 新版本 / `/lny-prd-iter` | **⑩ iter**：Read `lny-prd-iter/SKILL.md`；先只读核验当前最新版本的 ⑧ 评审终态、应有的 ⑨ SP 与未清台账，未闭合则停止建版并建议对应责任步；**禁止**被演示措辞改成静默 ⑩ |
| GoalProto | 用户目标为原型 / 演示 / 给老板看 / 先出个页面（且非「只要规格」），且 **无** 未清 I2、**非** 明确检查/估点/新迭代 | **§3.2**：当前版本静默补缺的 ②③④⑤ 再 ⑥；已齐则只 ⑥ |
| B | `ui_manifest.md` 不存在，或缺失页面/局部自定义UI组件索引，或 `ui/` 明细缺失/未与 `ui_manifest` 对齐，或 `main_spec` 第4章存在 `###` 小节或页面/组件/分包重复表 | **② ui**（若同时 C/D 也缺 → **§3.1 三件套批**，同轮连做 ②③④） |
| C | `api_spec.md` 不存在，或其 API 索引与 `ui_manifest`/`ui/` 页面关联明显不一致（缺关键接口行、编号规则冲突） | **③ api**（若同时 B/D 也缺 → **§3.1 批**；仅 C 缺则只做 ③） |
| D | `feature_spec.md` 不存在，或缺失 `feature/FEATURE-*.md` 明细目录，或 `FEATURE-*` 与 `PAGE-*` / `API-*` 引用明显断裂 | **④ feature**（若同时 B/C 也缺 → **§3.1 批**；仅 D 缺则只做 ④） |
| F | 用户明确要求单页 PRD，且 **B、C、D 已满足**，且 **无** I2-spec / I2-page 未清项 | **⑤ page**：Read `lny-prd-page/SKILL.md` |
| G-partial | **B、C、D 已齐**，无 `待②`～`待⑤`，`prototypes/` **已有至少 1 个**业务 `PAGE-*.html`，且 `ui_manifest` 仍有 active `PAGE-*` 缺对应 html（排除项不计入） | **⑥** 补齐剩余缺页。**「继续」也落盘**；禁止重做 ②③④⑤ |
| G2 | `versions/{latest}/` 存在且 `ui_changes.md` 中有新增/修改页面、对应 `PAGE-*.html` 在 `prototypes/` 下不存在，且 **B、C、D 已满足**，且 **无** `待②`/`待③`/`待④`/`待⑤`，且对应 `pages_prd` 已存在或台账标明 `ui直出` | 本轮是演示/原型目标，或用户明确要求生成/更新原型 → **⑥**。仅「继续」而无上述目标 → 若同时命中 **G-partial** 则走 G-partial；否则 **只建议** ⑥，**不落盘** |
| G | 用户明确要求生成/更新原型（未命中 GoalProto 措辞时的同义入口） | 见 **§3.2** |
| J | 无上述命中且 B、C、D 已满足 | 输出简短状态摘要：**当前产品规格（②③④）已齐**；可建议 **⑤** 单页 PRD / **⑥** 原型 / **⑦** 检查 / **⑧** 需求评审 / **⑨** 估点；**不**主动推销开新版本；默认 **不**擅自改文件 |

**跳步规则**：用户要原型但规格未齐 → **不拒绝**，走 **§3.2** 在当前版本静默补链。禁止用 HTML 代替规格。禁止静默 ⑩。
