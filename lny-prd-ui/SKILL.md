# 用户交互体验设计 `/lny-prd-ui`

本步是 **用户交互体验设计师**，不是「把页面上有什么抄进表格的人」。

要设计的是：这个页面 **怎么摆会更好看、人用起来更舒服、操作更丝滑**；该有的 **动效 / 微反馈 / 过渡** 要点名；该 **收起来、折叠、半屏、弹窗** 的要给形态和触发。控件清单只是载体。

**和下游的分工**：② 决定体验并写满 §2.3（夹具是**地板不是天花板**）；⑤ 把体验写进单页 PRD（不降级成线框）；⑥ 用套件实现 §2.3，并**必须落地舒适默认**（骨架/空态/失败可重试/过渡/语义列宽），即使 §2.3 漏写。禁止 ⑥ 发明新的业务跳转、字段或弹窗。

## 夹具速查（写 PAGE 前扫一眼）

夹具 `examples/mini-shop/` 是**已验证的地板**。用户**不必**自备设计规范：未另给时一律采用 [`reference.md`](reference.md) **§1.7.0 默认体验规范**。同类页按表落盘，然后 **§2.3 必须再写舒适默认**，禁止只抄控件名交差。细则 **§1.3.3 / §1.4.3 / §1.7**。

**移动端（MP）**

| 页型 | 夹具 | ② 必须写清 |
|------|------|------------|
| TabBar 宫格/首页 | PAGE-MP-001 | L0 **沉浸式**；**无页内顶栏**；Banner 下沉；金刚 4/5 列图标文字同底，或一排两张大卡（小图标与文案靠左）；列表卡封面 **1:1** |
| 列表 | PAGE-MP-002 | L0 **标准**；L1 **搜索行+筛选行贴顶**；横卡 **1:1**；半屏写清左/底/右与过渡；日期段用底半屏开始/结束签 |
| 展示/详情 | PAGE-MP-003 | 无 TabBar；L1 返回叠图上；主图 **16:9**；图文介绍；评论含 **时间行**，附图 **1:1、一排最多五张** |
| 表单 | PAGE-MP-004 | 无 TabBar；返回+标题；输入独立成行且 **右侧安全距**；选项=标签角标；下拉少选项中间弹窗、多则底半屏；滑动条（五步/无极）、底半屏日期/省市区、单图/多图/文件上传须点名；提交 **贴底** |
| 向导 / 分步 | PAGE-MP-005 | 无 TabBar；步骤条+分段进步条；当前步表单；可回上一步；**最后一步才提交**；中途离开要确认 |
| 设置 / 偏好 | PAGE-MP-006 | 无 TabBar；L0 **沉浸式**；封面顶栏 **两倍标题栏高度**（不要 16:9）；分组标题；一行一项开关 |

**桌面端（AD）**

| 页型 | 夹具 | ② 必须写清 |
|------|------|------------|
| D1-1 列表 | PAGE-AD-001 | 顶 **仅面包屑**；签在筛上 **整区切换**；勾选左冻 / 操作右冻定宽多余进「**更多**」；汇总左分页右贴底；**列宽按字段语义**（名称吃剩余，金额/状态/日期窄，禁止均分拉长）；**控件紧凑**（矮行、小内外距，一屏多看几行）；日期段筛选用月历点两次 |
| D1-2 表单 | PAGE-AD-002 | 顶仅面包屑；字段分区；保存/取消。**不要**套 D1-1 的紧凑行高 |
| 向导 / 分步 | PAGE-AD-003 | 顶仅面包屑；步骤条+分段进步条；当前步表单；可回上一步；**最后一步才提交** |
| 工作台 / 仪表盘 | PAGE-AD-004 | D1-3；首屏 3～4 张指标卡；主图/趋势区；下面才是待办或短表；指标可点则写清去哪。**禁止**套 D1-1 商品表 |
| 树 + 内容 | PAGE-AD-005 | D1-3；左树右内容；树当前项高亮；右区随选中切换，不要整页刷新 |
| 设置 | PAGE-AD-006 | D1-2 分组；分组标题；一行一项（开关/进入下级）；破坏性操作单独分组并确认 |

禁止：TabBar 页再写大标题；详情主图套列表卡 1:1；D1-1 所有列均分或用表单页大内边距。

**舒适默认（每页 §2.3 必写，无则写「无」并说明为何）**

| 项 | 要写清 |
|----|--------|
| 加载 | 骨架（列表/卡片/表），禁止空白白屏 |
| 空态 | 插图 + 一句人话 + 一个引导动作（或写「无数据时仅文案」） |
| 失败 | 可重试；列表失败页内 Alert，轻失败 Toast |
| 键盘与焦点 | 桌面：Tab 顺序合理、主按钮回车提交、焦点可见；触屏：不靠 hover |
| 首次进入 | 有空数据/权限/未配置时怎么一眼看懂；没有则写「无首次引导」 |
| 一屏节奏 | 首屏只打一件主事；次要进半屏/折叠/更多 |

**夹具没有的页型（禁止拿 D1-1 硬套）**

| 页型 | 骨架 | ② 必须写清 |
|------|------|------------|
| 分栏对照 | D1-3 | 两栏职责；哪一栏滚、哪一栏钉；主操作落在哪一栏。左树右内容用 PAGE-AD-005，不要另套商品表 |

## 开笔前

Read `lny-prd-master/framework-exclusions.md` 及本项目追加排除。不为框架通用已排除项建 `ui/PAGE-*`。Read `main_spec` §1.5「明确不做」（若有）：**禁止**为清单中的能力建 PAGE。**新立项只走目录化**（`ui_manifest` 只留索引 + `ui/` 明细）；旧「manifest 内嵌全文」只读兼容，禁止双轨扩写。

写任何 `ui/PAGE-*` 前必须 Read [`reference.md`](reference.md) **§1.7**（先 **§1.7.0 默认体验规范**，再舒适默认与夹具外页型），并在该页写 **§2.3**。移动端另读 **§1.3.3**。桌面 D1-1 另读 **§1.4.3**。先扫上方 **夹具速查**：同类页用夹具地板，再写舒适默认；不是夹具表里已有的页型就用「夹具没有的页型」表，禁止拿商品列表硬套。禁止只写「有个列表、有个按钮」就把球踢给 `/lny-prd-prototype`。用户另给交互规范时只覆盖冲突项，其余仍用 §1.7.0。

## 职责与禁止

- **负责**：以体验设计师身份产出 `ui_manifest.md` + `ui/PAGE-*.md` + `ui/COMP-*.md`（含 **§2.3 交互体验设计**）；`main_spec.md` **只写 §5 统计**。
- **禁止**：只列控件不设计体验；改第4章终端表；写 `api_spec` 字段；改 `prototypes/`；写预览壳机制（状态演示/postMessage/`map.html`）；在根规范「变更记录」表新增行；落盘 `pages_prd/_shell`（属 ⑤）；写阴影/字号/色值清单（动效用「快/中/慢」「过渡滑入」等，不写 ms/px）。仅当 PM 已说出点位或 AD 字典条目才写埋点；**禁止自拟埋点方案**。

COMP **编号必填** `COMP-{三位序号}`，与 `ui_manifest` §4「组件编号」列、`ui/COMP-*.md` 文件名一致。

## 局部自定义 UI 组件（判定）

满足其一即可建 COMP：多页复用，或多态展示。禁止按面积拆碎；同一状态机且视觉相邻 → 一个 COMP。单页 ≥3 个独立状态机/数据域 → 必须拆页。PAGE 纯组合，状态写在 COMP。详情与模板见 [`reference.md`](reference.md)。

## 写产物纪律

1. 开笔前 Read `main_spec` 第4章（只读）、§5、`ui_manifest` 与相关 `ui/` 明细。
2. 一次对话一条主线；先清单后落盘；整块写。
3. 收尾：更新 §5 统计；`versions/{版本号}/iteration_notes.md` 文末追加业务变更流水（非则跳过）。

## 执行步骤

1. 校验 `main_spec` 第4章终端；目标终端不在表中则停，交 ①。
2. 缺 `ui_manifest.md` / `ui/` 时按 [`reference.md`](reference.md) 创建索引骨架（立项兜底）。
3. 更新 `§3.2` 与 `ui/PAGE-*.md`：**结构（L/D）+ §2.3**（含舒适默认六项）。移动端落实 §1.3.3。夹具外页型落实速查表，禁止误套 D1-1。
4. 涉及 COMP：更新 §4 与 `ui/COMP-*.md`（状态矩阵 + **按下/成功/失败/过渡**，禁止只写 default）。
5. 更新 `main_spec` §5 统计；文末追加 `iteration_notes`（若有业务变更）。
6. **自检**：删掉该页 §2.3 后，⑥ 是否只能画出线框空盒子？是 → 没写够。舒适默认六项是否都有一句（或「无」）？夹具外页型是否误套了 D1-1？
7. 输出已改文件与页面编号。
