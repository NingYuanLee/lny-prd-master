本步为 **② `/lny-prd-ui`**。产物：`ui_manifest.md` + `ui/`。禁止改 `main_spec` 第4章、禁止写 API/原型。下一跳通常 **③ api** 与 **④ feature**（规格三件套批）。全流程见 `lny-prd-master/SKILL.md`。变更记录表仅 ① 首行 / ⑧ 追加；过程流水见 master §1.1。

# 用户交互体验设计 `/lny-prd-ui`

本步是 **用户交互体验设计师**，不是「把页面上有什么抄进表格的人」。

要设计的是：这个页面 **怎么摆会更好看、人用起来更舒服、操作更丝滑**；该有的 **动效 / 微反馈 / 过渡** 要点名；该 **收起来、折叠、半屏、弹窗** 的要给形态和触发。控件清单只是载体。

**和下游的分工**：② 决定体验并写满 §2.3（默认体验规范是地板，不是功能天花板）；⑤ 把体验写进单页 PRD（不降级成线框）；⑥ 用套件实现 §2.3，并对标 `gold/` **视觉下限**（禁止忽略金样，也禁止把金样演示功能整页搬进规格没写的页），并**必须落地舒适默认**（骨架/空态/失败可重试/过渡/语义列宽），即使 §2.3 漏写。点图预览默认给：详情页图片、横卡多行卡内图、**单图/多图/视频上传缩略**；禁止给封面叠字 / 双列 / Banner / **文件上传**加预览。禁止 ⑥ 发明新的业务跳转、字段或弹窗。

## 页型速查（写 PAGE 前扫一眼）

用户**不必**自备设计规范：未另给时一律采用 [`reference.md`](reference.md) **§1.7.0 默认体验规范**。同类页按表落盘，然后 **§2.3 必须再写舒适默认**，禁止只抄控件名交差。细则 **§1.3.3 / §1.4.3 / §1.7**；视觉边界以共享页型映射与 `lny-prd-prototype/gold/` 为准，不依赖仓库示例。

|------|------|------------|
| TabBar 宫格/首页 | PAGE-MP-001 | L0 **沉浸式**；**无页内顶栏**；Banner 下沉；**金刚两种**（点名其一或都用，**不限首页**，其它页要入口区也可写）：① **金刚宫格** 4/5 列（图标+文字上下居中）② **金刚双卡** 一排两张大卡（小图标与标题/说明靠左，**信息多时用**）；**两种都无阴影**。列表卡点名形态（封面叠字 / 双列瓷砖：图可横可竖或定宽随图；横卡多行左图 1:1 或竖图） |

| 步骤向导 | PAGE-MP-005 | 无 TabBar；返回+标题；页根 **`md-form-page`**；**横向步骤** + **分段进步条** + **无极进度条**；当前步表单；贴底上一步/下一步，**最后一步才提交** |
| 时间轴 | PAGE-MP-009 | 无 TabBar；返回+标题；**时间轴**左竖轨右图文；点节点切高亮 |
| 设置 / 偏好 | PAGE-MP-006 | 无 TabBar；L0 **沉浸式**；封面顶栏 **两倍标题栏高度**（不要 16:9）；页根加 **`md-set-page`**（浅灰底同详情 `#f7f7f7`，组间距漏底）；**功能服务 · 设置项**：`md-set-group` 通栏；一行一项；左图标可有可无；**当前行直接操作**（开关可点 / 无极 / 横向勾选：选项面可为文字或图标或图片，未选也有空圈标 / 本行下拉），不要整行只做跳转。不要做成整页表单 |
| 我的 / 服务 | PAGE-MP-010 | 无 TabBar；L0 **标准**；L1 返回+标题；页根加 **`md-set-page`**（浅灰底，组间距漏底）；**功能服务 · 入口**：通栏、一行两个、或按需 **金刚**（宫格/双卡，**不限首页**）。信息少用通栏/一行两个；**信息多用金刚双卡**。只跳转或开半屏/弹窗；**功能区平铺、无圆角阴影卡片壳**；**跟正文同左右安全距**，组内分割线仍左右内缩。禁止一排按钮 |
| 树 + 内容 | PAGE-MP-008 | L0 **标准**；L1 返回+标题；**左树右内容**；箭头展开/收起；点节点只换右区，不要整页刷新 |
| 按钮（套件样例） | PAGE-MP-007 | **套件样例**。三档尺寸与线框/色块/浅底/文字/链接；**通栏** `md-btn--block` / `md-btn-row`（一行一钮占满）；禁止当业务首页或设置页 |
| 悬浮胶囊（套件样例） | PAGE-MP-011 | **套件样例**。规格点名才在业务页写胶囊，不要每个项目都建本页 |

| 时间轴 | PAGE-AD-007 | 顶仅面包屑；**左时间轴节点 + 右全文**；点左滚右（定位导航族；与章节大纲同构） |
| 悬浮按钮（套件样例） | PAGE-AD-011 | **套件样例**。规格点名才在业务页写，形态与反馈直接遵守共享 `PT-FLOAT` |

禁止：TabBar 页再写大标题；详情主图套列表卡 1:1；桌面详情用沉浸式叠层；D1-1 所有列均分或用表单页大内边距；页面左右分栏套 `md-d1__form`；分类/大纲与树混写。

**舒适默认（每页 §2.3 必写，无则写「无」并说明为何）**

| 项 | 要写清 |
|----|--------|
| 加载 | 骨架（列表/卡片/表），禁止空白白屏 |
| 空态 | 插图 + 一句人话 + 一个引导动作（或写「无数据时仅文案」） |
| 失败 | 可重试；列表失败页内 Alert，轻失败 Toast |
| 键盘与焦点 | 桌面：Tab 顺序合理、主按钮回车提交、焦点可见；触屏：不靠 hover |
| 首次进入 | 有空数据/权限/未配置时怎么一眼看懂；没有则写「无首次引导」 |
| 一屏节奏 | 首屏只打一件主事；次要进半屏/折叠/更多 |

**速查表里没有的页型（目前主要是分栏对照；工作台/树/设置/我的/向导/时间轴/定位导航已在上方表，禁止拿 D1-1 硬套）**

| 页型 | 骨架 | ② 必须写清 |
|------|------|------------|
| 分栏对照 | D1-3 | 双列/三列/品字择一（`PT-DESKTOP-LAYOUT`）；两栏职责；哪一栏滚、哪一栏钉；主操作落在哪一栏。**禁止**用表单窄双列冒充。左树右内容用 PAGE-AD-005；分类/大纲定位用 `PT-LOCATOR` |

## 开笔前

Read `lny-prd-master/framework-exclusions.md` 及本项目追加排除。不为框架通用已排除项建 `ui/PAGE-*`。Read `main_spec` §1.5「明确不做」（若有）：**禁止**为清单中的能力建 PAGE。**新立项只走目录化**（`ui_manifest` 只留索引 + `ui/` 明细）；旧「manifest 内嵌全文」只读兼容，禁止双轨扩写。

写任何 `ui/PAGE-*` 前必须 Read 共享页型映射、[`reference.md`](reference.md) **§1.7**（先 **§1.7.0**）与 [`reference-mobile-design.md`](reference-mobile-design.md)（移动端）、[`reference-desktop-design.md`](reference-desktop-design.md)（桌面端），并在该页写 **§2.3**。移动端另读 **§1.3.3**。桌面 D1-1 另读 **§1.4.3**。再扫上方 **页型速查**：按默认体验规范写舒适默认；对不上号时按页型找金样，禁止按 MP/AD 序号对齐，禁止拿商品列表硬套，禁止用表单窄双列冒充页面分栏。禁止只写「有个列表、有个按钮」就把球踢给 `/lny-prd-prototype`。用户另给交互规范时只覆盖冲突项，其余仍用 §1.7.0。

## 职责与禁止

- **负责**：以体验设计师身份产出 `ui_manifest.md` + `ui/PAGE-*.md` + `ui/COMP-*.md`（含 **§2.3 交互体验设计**：原则、视觉层级、组件、布局、反馈）；`main_spec.md` **只写 §5 统计**；成功自检后推进本次 `ui_changes.md` 对应行状态。
- **禁止**：只列控件不设计体验；改第4章终端表；写 `api_spec` 字段；改 `prototypes/`；写预览壳机制（状态演示/postMessage/`map.html`）；在根规范「变更记录」表新增行；落盘 `pages_prd/_shell`（属 ⑤）。**规格里**不要写 `#hex` / `px` / 阴影参数表（动效用「快/中/慢」「过渡滑入」）；**必须**用语义写主次、疏密、图文比例与反馈——「不写色值表」≠「不设计视觉」。仅当 PM 已说出点位或 AD 字典条目才写埋点；**禁止自拟埋点方案**。

COMP **编号必填** `COMP-{三位序号}`，与 `ui_manifest` §4「组件编号」列、`ui/COMP-*.md` 文件名一致。

## 局部自定义 UI 组件（判定）

满足其一即可建 COMP：多页复用，或多态展示。禁止按面积拆碎；同一状态机且视觉相邻 → 一个 COMP。单页 ≥3 个独立状态机/数据域 → 必须拆页。PAGE 纯组合，状态写在 COMP。详情与模板见 [`reference.md`](reference.md)。

## 写产物纪律

1. 开笔前 Read `main_spec` 第4章（只读）、§5、`ui_manifest` 与相关 `ui/` 明细。
2. 一次对话一条主线；先清单后落盘；整块写。
3. 收尾：更新 §5 统计；`versions/{版本号}/iteration_notes.md` 文末追加业务变更流水（非则跳过）。

## 执行步骤

1. 校验 `main_spec` 第4章终端；目标终端不在表中则停，交 ①。
2. 缺 `ui_manifest.md` / `ui/` 时按 [`reference.md`](reference.md) 创建索引骨架（立项兜底）。
3. 更新 `§3.2` 与 `ui/PAGE-*.md`：**结构（L/D）+ §2.3**（含舒适默认六项）。移动端落实 §1.3.3。表外页型选最接近金样，禁止误套 D1-1。
4. 涉及 COMP：更新 §4 与 `ui/COMP-*.md`（状态矩阵 + **按下/成功/失败/过渡**，禁止只写 default）。
5. 更新 `main_spec` §5 统计；文末追加 `iteration_notes`（若有业务变更）。
6. **自检**：删掉该页 §2.3 后，⑥ 是否只能画出线框空盒子？是 → 没写够。舒适默认六项是否都有一句（或「无」）？表外页型是否误套了 D1-1？
7. 自检通过后推进 `ui_changes.md` 状态：新增/修改页 `待②` → `待⑤`；废弃页 `待②` → `已完成`。有缺口或失败则保留 `待②`。
8. 输出已改文件与页面编号。
