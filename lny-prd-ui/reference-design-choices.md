# 从内容和任务推导视觉选型

② 设计新页、重画关键页面，或⑥发现既有布局妨碍任务时使用。沿用已验证的模式时，只说明这次内容和使用条件仍匹配。以下问题由 AI 自问，选择会改变本页决定的几项即可。

这些方法仅在能帮助作决定时使用。可以提出下文以外的方向，或保留现状；用当前项目解释选择即可。简单局部修改直接执行，不要求列备选、制作多版或逐项作答。

## 先发现值得设计的问题

从项目资料中选一个具体使用时刻：谁带着什么问题来到这一页，看见什么才能决定下一步？标清依据来自已确认的产品决定、真实内容或待验证的假设。旧 HTML 中已有某种控件，只能证明它曾被采用。若某布局已由产品明确指定，按规格实现，把观察到的代价反馈给②；调整该决定沿用项目现有变更流程。

读一遍真实标题、关键字段、素材和异常状态。把组件请求改写成可以检验的问题。例如「如何做推荐卡」可以改问「用户能否在列表里看见区分这两项的字段」。从最可能导致误读、漏看或失去品牌辨识度的一处开始。

## 对关键分歧做取舍

- **阅读顺序**：写出预期第一眼和下一眼。找出画面中尺寸最大、对比最强以及距离最近的元素，检查它们是否把相关内容归在一起。强调一个入口之前，说出它会挤走什么；异常状态可以改变优先级。
- **视觉方向**：把品牌词翻译成具体的画面决定。要表达工艺，就选择能看清材料或工序的主体；要说明服务场景，就选择能看清人物、动作和环境关系的构图。分别在实际裁切比例、标题长度和字体回退条件下判断。品牌素材不足时用现有可实现方案并说明取舍。
- **结构与行为**：内容靠什么区分，是否需要并排比较，滚动或切换之前必须知道什么？据此选择图文比例、分组、导航和动效。信息充分时直接定案。两个方向都会显著改变体验且现有证据不足时，用同一份代表性内容和视口试排最小的争议区域，仅改变待验证的因素。
- **决策落点**：将选择、关键依据和可推翻它的观察写入既有 PAGE §2.4。例：「选按行对齐，因为调度员要比较多条记录的到期时间；若窄屏把到期时间挤出可视区，先调整字段优先级再复验。」常规选型由 AI 完成，询问条件沿用总控协议。

## 回到 HTML 看选择是否成立

让真实内容进入目标视口，执行关键动作，并在相关时检查长标题、缺图、滚动或异常状态。记录观察，例如“产品区已露出，名称仍在屏外”。若换颜色无法解决，回到信息顺序、布局或素材重新选型；若问题出在字距、对齐或裁切，就局部修正。比较前后同一任务能看见或完成什么。像素差异只说明画面变动。作者走查、浏览器检查和真实用户测试应分别标明。

## 方法出处

下列是方法来源。上面的触发条件、示例与落盘约定是为本技能编写的应用规则。

- Design Council，先界定问题，再探索与小范围检验解法。[The Double Diamond](https://www.designcouncil.org.uk/resources/the-double-diamond/)
- Kelley Gordon，运用尺度、层级、平衡、对比和分组引导阅读。[5 Principles of Visual Design in UX](https://www.nngroup.com/articles/principles-visual-design/)
- IBM Design Language，根据叙事目的选择影像题材与表现方式。[Photography](https://www.ibm.com/design/language/photography/overview/)
- GOV.UK Design Community，按待验证的问题决定原型精度，用代码原型检验真实交互。[Making prototypes](https://www.gov.uk/service-manual/design/making-prototypes)
