## 1. 阅读说明与清单结构约定

> **导读**：本文件仅维护 §2～§4 索引与 §5 全局说明。页面/组件详述落在 `ui/PAGE-*.md`、`ui/COMP-*.md`，禁止在本文件重复正文。详规见 `lny-prd-ui/SKILL.md`。

### 1.1 操控形态定义（全文区分基准）

| 形态 | 判定依据 | 典型终端（以项目 `main_spec` → 第4章终端说明 为准） |
|------|----------|------------------------------------------|
| **移动端** | 以 **手指触控** 为主完成主要交互 | 小程序、App、触屏 H5 等 |
| **桌面端** | 以 **鼠标指针**（及键盘辅助）为主完成主要交互 | PC 网页、管理后台 Web 等 |

### 1.2 视觉描述规则（两端适用）

**自底至顶（层级优先）** → **自上而下（同层多模块）** → **自左至右（左右布局优先）** → **自外至内（父子结构由内向外展开）**。

分页面须在以上顺序之上，按操控形态分别落实 **§1.3**（移动）或 **§1.4**（桌面），不得以本条替代 **§1.3 / §1.4** 的结构约定。

### 1.3 移动端：层级与布局

#### 1.3.1 层级一览表（L0～L5）

| 序号 | 层级名称 | 简要描述 |
|------|----------|----------|
| L0 | 系统层 | 真机预览状态栏（固定顶演示，不随滚）；安全区（左右下+四角，含圆角/曲面屏）；系统手势、壳层 TabBar 等 |
| L1 | 固定导航层 | 页内顶栏、业务固定顶/底栏等 |
| L2 | 主体滚动层 | 主内容滚动容器 |
| L3 | 模块容器层 | 卡片、分区、列表、表单块 |
| L4 | 内容元素层 | 标题、文案、按钮、图、输入、标签 |
| L5 | 浮层与反馈层 | 弹窗、抽屉、Toast、遮罩、加载态 |

#### 1.3.2 布局偏好（书写要点）

- 优先采用 **自动弹性容器布局**（如弹性盒、自适应流式/栅格），避免过多写死像素分区。
- 与 **`L0`～`L5`** 叙述一致。
- **触屏硬规则**见 **§1.3.3**：必须写进 `ui/PAGE-*.md` 的 L0/L1/L5，禁止留给 ⑥ 去猜。

#### 1.3.3 触屏端体验硬规则（MP / H5 / APP 必守）

写移动端 `ui/PAGE-*` 时按本表落盘。⑥ 只负责用套件类名实现，**不得**在规格未写时自行发明，也**不得**因规格漏写而画成带顶栏的线框页。

| # | 规则 | 规格怎么写 | 禁止 |
|---|------|------------|------|
| 1 | **底栏固定** | 壳层 TabBar、页内主操作条（提交/购买/下一步）写在 **L1**，并写明「贴底固定、不随 L2 滚动」；有 Home Indicator 时底栏计入安全区 | 底栏画在滚动内容末尾、滑走消失 |
| 2 | **有 TabBar 则无页内顶栏** | L0 写 TabBar；L1 写 **「无页内顶栏」**。Tab 文案即当前页身份。仅 **无 TabBar 的二级页** 才写返回顶栏 | TabBar 页再写「顶栏标题「首页」」；顶栏+底栏重复显示同一页名 |
| 3 | **小程序胶囊避让** | L0 写明：页内可点按钮、搜索、更多 **不要顶到右上胶囊**。原生状态栏的电量/信号 **靠右**，不要为胶囊把它们往里挤 | 自定义顶栏汉堡/搜索/分享顶到胶囊上；把状态栏信号留出一大块空白 |
| 4 | **图文列表卡 1:1 封面** | COMP 或 L3 写「封面 **1:1**」。宫格卡与横卡（上图下文 / 左图右文）均正方形图 | 列表卡用 16:9；圆图+无比例 |
| 5 | **首屏背景/slogan 下沉** | 若 L2 **第一个模块**是背景图、slogan、Banner：写「**下沉式**」并配 L0 **沉浸式**（状态栏透明叠在图上），**不要**先不透明状态栏再图 | 先实心状态栏，下面再放 Banner |
| 6 | **常用浮层与动效** | 规格出现则必须点名形态：Banner 轮播、金刚区、左/底/右半屏、确认框、Toast；并写「显隐 **过渡** 而非瞬切」 | 用「弹出一层」含糊带过；不写方向（左/底/右） |
| 7 | **触控反馈** | L4 写可点元素「无默认下划线；按下有反馈；热区 ≥44px」 | 依赖 hover 当唯一反馈；链接带下划线当按钮 |
| 8 | **圆角 / 曲面屏安全距** | L0 写明「左右下及四角留安全距」：可点控件、主文案、Tab、半屏把手 **不贴物理圆角/曲面**；**状态栏本身不套安全距**；装饰图可铺满但内容落在安全区内 | 按钮/文字顶到屏幕圆角或曲面边缘 |
| 9 | **顶栏模式：沉浸式 / 标准** | L0 **必写其一**：**沉浸式**（状态栏背景透明，内容从屏幕顶铺起）或 **标准**（状态栏背景不透明，内容从状态栏下开始）。下沉 Banner/首屏必须用沉浸式 | 不写模式；沉浸式却用实心底栏；标准页把内容顶到状态栏后面 |
| 10 | **触屏输入独立成行** | 每个输入/开关/选项组单独一行，组与组之间留空防误触；禁止两列并排输入；**输入框左右不贴屏，右侧须有安全距** | 触屏表单两列挤在一起；输入右边框贴死屏幕 |
| 11 | **表单单选/多选＝标签** | 表单、筛选里的选项写成 **标签**；选中时右上角 **对号角标**，未选中无角标 | 表单里用桌面那种左侧小圆圈/小方块当选项 |
| 12 | **列表单选/多选＝左侧圆/方** | 列表行、表格行仍用左侧圆圈（单选）/ 方块（多选） | 列表行做成标签角标 |
| 13 | **列表搜索行 + 筛选行贴顶** | 列表页 L1 写「搜索框行」与「筛选行」**贴顶固定、不随 L2 滚动**；L2 只滚卡片。本页确无搜索或筛选须写明「无搜索」/「无筛选」 | 搜索、筛选跟列表一起滑走 |
| 14 | **展示类（详情/内容）** | 无 TabBar 的二级页：L1 返回（避让胶囊）；主内容只读（图/文/规格）；首屏大图用 **沉浸式下沉**，非列表图片默认 **16:9**；可贴底次要操作，但不是提交表单 | 展示页做成可编辑表单；有 TabBar 再叠返回顶栏；详情主图做成 1:1 列表卡 |
| 15 | **表单类** | 无 TabBar；L1 返回+标题；输入独立成行且右侧留安全距；选项用标签角标；规格出现的滑动条/底半屏三级选择/上传须点名形态；**主操作条贴底固定**提交 | 提交按钮埋在滚动末尾；两列输入；输入贴右边；触屏用原生日期框 |
| 16 | **非列表图片默认 16:9** | 详情/内容页的主图、介绍配图等 **非列表卡片** 图片写「**16:9**」。列表卡仍走规则 4 的 **1:1**。评论附图等缩略图若规格写 1:1 则从其规定 | 详情主图、正文配图套用列表卡 1:1 |

**补全（与上表一并执行）**：

- **二级页返回**：无 TabBar 时 L1 才写左侧返回；右侧仍避让胶囊。
- **主操作条 vs TabBar**：有 TabBar 时不要再叠一条「返回+标题」；无 TabBar 的展示次要操作、表单提交用贴底 `主操作条`。
- **列表工具条**：搜索框单独一行，筛选（含打开半屏的「筛选」）单独一行，二者都在 L1，不进滚动区。
- **金刚区**：默认 4 或 5 列，图标与文字 **上下排在同一块方形底** 上，居中；另有 **一排两张大卡**（`md-king--pair`）：小图标与标题/说明 **全部靠左**，禁止大卡里再居中。禁止图标单独成色块；容器留安全内边距；宫格文字不超过四字；点击写清跳转或打开哪一侧半屏。
- **Banner**：有指示点；自动轮播；点击若无详情页则写「无出页」。首页/运营 Banner 默认 **2:1**（与套件 `md-swiper` 一致），不要写成列表卡 1:1。
- **半屏**：左/右为侧滑（宽约 80%）；底为高度约 50%～70% 的面板；须有遮罩，点遮罩关闭。
- **确认 vs Toast**：破坏性操作（清空/删除）用确认框；轻反馈（已筛选/已复制）用 Toast。
- **触屏 Toast**：屏幕中央；半透明黑底圆角；白图标 + 白字。禁止贴底长条、禁止彩色实心底。
- **带图标方形按钮**：图标与文字上下排在 **同一背景容器** 内，容器留安全内边距；禁止图标单独一块底、文字露在容器外。
- **触屏输入**：每个输入控件独立成行，上下留空防误触；输入框右侧留安全距，不贴屏边。
- **触屏单选/多选**：表单、筛选用标签（选中右上对号角标）；列表行仍用左侧圆圈/方块。
- **触屏滑动条**：五步离散须有刻度与当前档；无极连续须显示当前值。
- **触屏下拉**：选项少（≤6）中间弹窗，选项多底半屏；列表均可上下滚动。禁止系统原生 `select` 面板。
- **触屏日期 / 省市区**：底半屏、三级联动（年-月-日 / 省-市-区），点遮罩关闭、显隐过渡。禁止原生 `type=date`。禁止给省市区加「开始日期 / 结束日期」签。
- **触屏日期段**：底半屏；「开始日期 / 结束日期」两个签，各年-月-日。禁止两个原生日期框硬凑。
- **触屏上传**：单图/视频点选后预览并可更换；多图可添加可删除；文件上传显示文件名。
- **不用 hover 当唯一态**：MP/H5/APP 的选中、按下必须有非 hover 视觉。
- **圆角 / 曲面屏**：左右下留边；四角避开圆角半径；**顶部状态栏是固定演示层，不套安全距、不随页滚**。禁止把 Tab、返回、金刚首尾项、半屏贴死在角上。
- **顶栏模式**：每页 L0 点名沉浸式或标准；沉浸式状态栏透明，标准不透明。触屏顶栏四种择一：16:9+slogan（无页内顶栏）；16:9+返回标题；标准高度返回标题；两倍高度封面+标题（勿拉成 16:9）。

落盘口诀：L0 顶栏模式（沉浸式透明 / 标准不透明）+ 安全区（左右下+四角）与胶囊；L1 只放真正固定的底/顶（列表=搜索+筛选贴顶；展示/表单=返回；提交贴底）；L2 下沉首屏用沉浸式；L3 列表卡 1:1、详情非列表图 16:9；L5 写清半屏方向与过渡。

### 1.4 桌面端：布局结构类型与内容区固定结构

> 与 §1.3 对齐，布局规则落盘于 `ui/PAGE-*.md`。

#### 1.4.1 布局与内容区一览表

| 序号 | 类型 | 简要说明 |
|------|------|----------|
| D0 | **空白布局** | 独立全页，无业务壳或极简顶栏。`ui/PAGE-*.md` 骨架码 **D0**（**勿**写 **D1**）。 |
| D1-1 | **标准内容区** | **须**「顶栏 + 侧栏 + **面包屑** + 内容区」壳内。内容区**顶部就是面包屑，不要页内大标题**。自上而下：**面包屑**→**页内签（如有，在筛选上方）**→**搜索栏**→**功能栏**→**列表区**（含**固定宽度操作列**）→**汇总（左）+分页（右）**。骨架码 **D1-1**。 |
| D1-2 | **表单内容区** | **同上**壳，内容区顶部同样是面包屑、无页内大标题。**数据展示** / **数据录入**；**编辑** / **保存** / **取消**。骨架码 **D1-2**。 |
| D1-3 | **自定义内容区** | **同上**壳；非标结构在 **`ui/PAGE-*.md`** 按模块写。骨架码 **D1-3**。 |
| D5 | **浮层与反馈层（桌面）** | 叠在 **D0 / D1-1 / D1-2 / D1-3** 之上；记 **D5**，**勿**用 **L5**。 |

#### 1.4.2 桌面端书写要点（硬约束与指针）

- **D1-1**：**`ui/PAGE-*.md`** 须写全 **搜索栏 / 功能栏 / 列表区 / 汇总+分页**（有页内签时还须写签）。
- **硬约束**：禁止在 `ui/PAGE-*.md` 中使用 `api/API-*.md` 未定义的业务字段。
- **列表硬规则**见 **§1.4.3**：页内签、贴底分页与横向滚动条、冻结勾选列/操作列、操作列定宽与「更多」下拉、汇总左分页右、列宽按字段语义、列表页紧凑密度。必须写进 `ui/PAGE-*.md`，禁止留给 ⑥ 去猜。

#### 1.4.3 桌面端列表硬规则（PC / AD 的 D1-1 必守）

写桌面列表页时按本表落盘。⑥ 只负责用套件类名实现。

| # | 规则 | 规格怎么写 | 禁止 |
|---|------|------------|------|
| 1 | **页内签在筛选上方、整区切换** | 有页内签时写在 **搜索栏之前**；点签时 **整块切换** 搜索栏、功能栏、列表区、汇总+分页，不是只换表格行 | 签放在筛选下方或工具栏里；点签只过滤表格、筛选区还留着上一签的条件 |
| 2 | **汇总分页贴底** | 汇总栏+分页栏 **贴在内容区底部固定**，不随表格行上下滚走。仅当本页写明「分页跟表一起滚」才例外 | 分页画在表格最后一行下面、被行撑出视窗外 |
| 3 | **表头横向滚动条贴底** | 列表左右溢出时，**横向滚动条贴在表格可视区底部**（紧挨分页上方）。无特殊说明不得把横向滚动条悬在表中间 | 宽表只在首屏中部出现横条，底部分页却看不到横条 |
| 4 | **操作列右侧冻结** | 操作列 **固定在表右**，左右滚中间列时操作列不跟着走 | 操作列跟中间列一起横滑消失 |
| 5 | **勾选列左侧冻结** | 有勾选/选择列时 **固定在表左**，左右滚时不跟着走。无勾选列则写「无勾选列」 | 勾选列跟中间列一起横滑消失 |
| 6 | **冻结列内侧浮层阴影** | 左冻结列的 **右侧**、右冻结列的 **左侧**（对着滚动区的那一侧）有轻微阴影，看起来压在中间列上 | 冻结列无内外之分、或把阴影画在贴边外侧 |
| 7 | **内容区顶部是面包屑** | D1-1 / D1-2 写「顶部 **面包屑**，**无页内大标题**」。当前页名只出现在面包屑末项 | 面包屑上方再写一遍「商品列表」大标题 |
| 8 | **操作列定宽，过多收「更多」** | 操作列 **固定宽度**；超过约两个操作时，首个可留在列内，其余收进 **「更多」**，点击后下拉再出按钮 | 操作列被一排按钮撑得很宽；按钮多了仍横排挤开 |
| 9 | **汇总左、分页右** | 汇总栏+分页栏同一行贴底：**统计信息靠左**（如共 N 条），**分页器靠右**（每页条数、页码） | 统计和页码挤成一堆或平均散开 |
| 10 | **列宽按字段语义** | 写清各列大致宽窄：名称/标题/说明 **吃剩余宽度**；金额、状态、短码、数量 **窄**；日期 **刚好放下 `YYYY-MM-DD`**；勾选与操作列 **定宽**。禁止所有列均分，也禁止被表格 `min-width` 拉成空荡长条 | 每列一样宽；短字段列被拉得很长、名称列却挤成两字 |
| 11 | **列表页紧凑密度** | D1-1 写「控件 **上下高度、内外距紧凑**，一屏多看几行」。面包屑、签、搜索栏、功能栏、表头表行、分页都走紧凑，不要用 D1-2 表单那种大内边距 | 列表页行高/内边距按表单页来，一屏只能看见三四行 |

**补全（与上表一并执行）**：

- 无页内签的 D1-1 须写「无页内签」，不要空缺让 ⑥ 随便加签。
- 中间列可以左右滚；冻结列背景实底，避免透出滚动内容。
- 弹窗内的小表若列少、不横溢，可不冻结；主内容区大表默认按上表。

落盘口诀：签在筛上、点签换整区；分页与表横条贴底；勾选钉左、操作钉右定宽多余进「更多」；汇总靠左、分页靠右；内容区顶只有面包屑；列宽按语义（名称宽、金额/状态/日期窄）；列表页紧凑多看行。

### 1.5 `ui/` 明细体例（页面与组件）

#### 1.5.1 `ui/PAGE-*.md`

### 1.7 交互体验设计（两端必守，本步主责）

② 的产出不是「页面上有什么」，而是 **人怎么用这个页面会舒服**。⑤⑥ 不得把本节当成可选项。

#### 1.7.0 默认体验规范（用户未另给规范时必用）

用户不必自备 Apple / Ant / 公司设计体系。未明确另给时，本包用这一份。**皮肤**仍是套件（Material 浅色 `md-*`），禁止另起品牌色/字体/圆角。**行为**按本表。用户另给规范时：只覆盖冲突句，其余仍用本表。禁止用「没有设计规范」为借口只抄控件名。

来源（只取行为，不取皮肤）：系统状态可见、主路径在页内、破坏性确认、轻反馈不打断——与常见可用性启发式及 Material 行为条款一致；触屏/桌面结构仍走 **§1.3.3 / §1.4.3**。

| # | 默认 | ② 怎么写 | ⑥ 落地 |
|---|------|----------|--------|
| 1 | 一屏一件主事 | 「首屏只打 {一件}；其余进半屏/折叠/更多」 | 首屏不堆第二个主任务 |
| 2 | 等待可见 | 「先骨架；空=插图+人话+一个动作；失败可重试」 | `md-skeleton` / `md-empty--illus` / Alert 或 Toast |
| 3 | 收纳分层 | 主路径页内；筛选次要半屏/抽屉；少数字段弹窗；多字段才整页 | 禁止主内容只活在弹窗里 |
| 4 | 一个主按钮 | 「主操作一个；超过 3 个次要进更多」 | 主按钮 `contained`；次要 `text`/`outlined` 或 `data-menu` |
| 5 | 说人话 | 按钮用动词；空态写下一步，禁止只写「暂无数据」交差 | 空态 `__title`+`__text`+可点动作 |
| 6 | 可退可停 | 返回/取消/上一步；提交中禁用防连点 | 向导可回上一步；提交按钮 loading/禁用 |
| 7 | 破坏性要确认、轻结果不打断 | 「删/清空=确认框；已保存/已复制=Toast」 | `ProtoPage.confirm` vs `snackbar` |
| 8 | 触屏不靠 hover；桌面焦点可见 | 触屏按下态；桌面 Tab/回车/焦点圈 | 套件按下态 + `:focus-visible` |
| 9 | 浮层过渡、禁止闪白 | 「半屏/弹窗/签过渡滑入或淡入」 | `openDrawer` / `openDialog` / 签 `data-panel` |
| 10 | 页型用对骨架 | 列表紧凑语义列；设置一行一项；向导最后才提交；工作台指标+趋势+待办 | 对金样，禁止拿 `desktop-list` 硬套 |

#### 1.7.1 设计问题（写页前自问，答案写入 PAGE §2.3）

| 问 | 要决定的事 | 写进规格的样子 |
|----|------------|----------------|
| 好看 | 首屏主次、留白节奏、图文比例、固定区 vs 滚动区 | 「首屏只打 Banner+金刚；商品在下；TabBar 贴底」 |
| 舒服 | 一屏几件事、热区、会不会挡视线（胶囊、底栏、弹窗、圆角/曲面四边四角） | 「筛选不占首屏；进右半屏；控件不贴屏角」 |
| 等待 | 加载 / 空 / 失败长什么样 | 「列表先骨架；空态插图+去添加；失败 Alert 可重试」 |
| 键盘 | 桌面 Tab/回车/焦点；触屏不靠 hover | 「回车提交主按钮；焦点圈可见」 |
| 第一次 | 没数据、没权限、没配好时第一眼 | 「空列表引导去新增；无则写无首次引导」 |
| 丝滑 | 哪些切换要过渡、哪些可以瞬切 | 「半屏过渡滑入；Tab 内容淡入；禁止闪白」 |
| 动效 | 轮播、展开、骨架、成功态 | 「Banner 自动轮播+指示点；骨架脉冲」 |
| 微反馈 | 按下、禁用、成功、失败 | 「按下缩放；成功居中 Toast（半透明黑底白字）；失败 Alert；禁用不可点」 |
| 收纳 | 默认露出 vs 折叠 vs 半屏 vs 弹窗 vs 新开页 | 见下表 |

#### 1.7.2 收纳决策（默认选左列，例外写进 §2.3）

| 场景 | 默认 | 不要 |
|------|------|------|
| 主路径浏览/购买 | 页内直出 | 主内容只在弹窗里 |
| 筛选、次要设置、说明 | 半屏 / 抽屉 / 折叠 | 无必要就新开整页 |
| 查看少量字段 | 展示弹窗或半屏 | 为三五条字段开新页 |
| 编辑少量字段 | 表单弹窗 | 能弹窗却整页跳转（字段很多才整页） |
| 破坏性（删/清空/不可逆） | 确认框 | 只 Toast 或直接做 |
| 轻结果（已复制/已筛选/已保存） | Toast | 模态打断 |
| 一排超过 3 个次要操作 | 更多菜单 / 滑动露出 | 工具栏堆满主按钮 |
| 长说明、规则、注释 | 折叠或气泡 | 首屏长文 |

#### 1.7.3 动效与反馈（写语义，不写 CSS）

用 **快 / 中 / 慢** 或 **过渡滑入 / 淡入 / 缩放按下**，禁止写 ms、px、色值。⑥ 用套件默认时长实现。

- **必须过渡（禁止瞬切）**：半屏/抽屉/弹窗开闭；页内签切换的内容区；Banner 轮播。
- **必须微反馈**：可点控件的按下态；主按钮提交中的 loading/禁用；成功与失败分流（Toast vs Alert/确认）。
- **桌面**：悬停可作增强，**不能**当唯一可辨认态（仍要有按下或焦点态）。

#### 1.7.4 写完自检

若删掉 PAGE **§2.3** 只剩 L/D 控件名，⑥ 只能画出线框 → **本页未完成**。未另给规范却不按 **§1.7.0**（一屏一件主事 / 空态无动作 / 轻结果用了模态）→ **本页未完成**。移动端 L0 未写左右下+四角安全距，或未点名沉浸式/标准 → **本页未完成**。桌面 D1-1 有列表却未写分页贴底/操作列右冻（有勾选则左冻）或列宽语义/紧凑 → **本页未完成**。§2.3 未写加载/空态/失败（或未声明「无」）→ **本页未完成**。工作台/树/设置/向导/分栏却写成 D1-1 商品表 → **本页未完成**。

#### 1.7.5 舒适默认（② 必写，⑥ 必落地）

即使页很简单，下列默认也成立。② 用一句话点名；⑥ 用套件实现。② 漏写时 ⑥ **仍须落地**，不算发明业务。

| 默认 | ② 怎么写 | ⑥ 用什么 |
|------|----------|----------|
| 加载不是白屏 | 「先骨架再出数」 | `md-skeleton` / `md-skel-host` |
| 空不是一行灰字 | 「插图+人话+一个动作」 | `md-empty md-empty--illus` |
| 失败能接着干 | 「可重试；列表 Alert，轻操作 Toast」 | `md-alert` / `ProtoPage.snackbar` |
| 点得有回馈 | 「按下缩放；禁止只靠 hover」 | 套件按钮已有按下态 |
| 浮层不瞬切 | 「半屏/弹窗/签过渡」 | `ProtoPage.openDrawer` / `openDialog` |
| 表列宽与密度 | D1-1 语义列宽+紧凑 | `md-col-*` + `md-d1--list` |
| 键盘与焦点 | 「Tab 顺序合理；主按钮回车；焦点可见」 | 套件 `:focus-visible`；触屏不靠 hover |
| 首次进入 | 「没数据/没权限时第一眼；无则写无」 | 用空态/Alert 说清现状；禁止另造引导层（除非 §2.3 写了） |
