### 总体与数据源

- 与 UI/API 根索引及明细文件同源（优先 `ui/`、`api/`）；**不**重复 `api/` 业务字段表全文；**不**编造规格未出现的字段名。

### 1. 基本信息

- **页面编号**：`PAGE-*`，与 `ui_manifest` **页面清单**、`ui/PAGE-*.md` 同源。
- **页面名称 / 所属终端 / 所属模块 / 路由**：从 `ui_manifest` §3.2 页面注册表读取；终端名称与 `main_spec` **第4章终端说明** **逐字一致**。
- **所属版本**：与当前 **`versions/{版本号}/`** 一致。
- **操控形态**：**仅**「移动端」或「桌面端」，与 **`ui/PAGE-*.md` → 基本信息表** **一致**；**不**在基本信息表抄 L/D 骨架码。
- **MasterGo**：从 `ui/PAGE-*` 明细读取；无则 **无**。
- **不写**：接口编号汇总表（见 **第 5 节**）。
- **与根规格关系（必填）**：紧接 **`## 1. 基本信息`** **表后**，落盘 **`> …` 引用块**（可多行简短列表，**不必**长篇）。必须让读者 **一眼**分清四份根文档分工，建议固定四件事：（1）布局分区：**`ui/PAGE-*`**；（2）接口语义：**`api/API-*`**；（3）功能规则：`feature_spec.md` / `feature/FEATURE-*`；（4）合法 `PAGE-*` 与跳转全集：**`ui_manifest.md` §3** / `ui/`。**禁止**在该引用块粘贴本 SKILL「产出具约束」全文或教学方法论。

### 2. 用户故事（本页）

单页 **第 2 节** 落盘 **仅** `## 2. 用户故事（本页）` + **`US-*` 表**。

- **与 `main_spec.md` → 1.2 的区分**：**1.2** 为产品级 **需求故事** 表（可含用户价值、运营、合规、迁移、技术使能）；本节 **仅** 本页界面内可验证的「我要 / 以便」，**禁止**整表或无关行迁入。可 **对照 1.2** 裁剪角色与价值，并结合 **`ui/PAGE-*.md`** 的目标与任务。
- **与 1.2 的关系**：价值 **不与 1.2 矛盾**；**粒度、`US-*`、措辞** 与 **1.2** **区分**，**勿**沿用 1.2 行号或表结构。
- **与第 3 节**：条数按页裁剪；**`US-*`** 可被第 3 节引用（如「见 US-1」）。
- **补缺（可选）**：当 **`ui/PAGE-*.md`** 对本页 **可操作路径或验收粒度** 偏粗时，允许加厚本表。

### 3. 页面模块详述

- **整页线框（ASCII，默认必填）**：在 **`## 3. 页面模块详述`** 标题下、**第一个 `###` 分区之前**，用 **代码围栏**（`~~~` 或 **```** 均可）写 **自上而下** 的整页线框（`+--` / `┌` 等随意，**须可读**）。**须**与 **`ui/PAGE-*.md` → §2 页面层级** 的 **分区顺序、上下叠放、主辅区关系** **一致**，供下游 **AI / 代码生成** 对齐 **布局与路由挂载点**。**⑥ 出原型时只取分区顺序，禁止把线框画成空盒子或降质页**；视觉下限是 `lny-prd-prototype/gold/`（对标密度与类名，禁止照搬金样演示功能，也禁止忽略金样）。触屏页还须落实 `lny-prd-ui` **§1.3.3**。桌面 D1-1 还须落实 **§1.4.3**（含列宽按字段语义、列表页紧凑）。**需求描述 ≠ 可见标题**：见 `lny-prd-ui/reference/ui-manifest-template.md` **§1.3.5**——立项/US/Feature 的分区称呼（如「功能入口区」）**不得**画成线框里的可见大标题行；金刚/入口区用 `[结构标注]` 或图标+短标签网格即可。仅当 PM 要求用户可见时，线框才可画对应标题文案。仅当本页 **无实质 UI**（如纯重定向占位）时，围栏内写 **一行** `无 UI 线框` 即可。页型顺序见 `lny-prd-page/SKILL.md` **三步对照** 与 **页型速查**（按页类型，禁止按 MP/AD 序号对齐）。
- 顺序与分区：严格按 **`ui/PAGE-*.md` → §2** 自上而下；每个 PAGE 分区对应本文件一个 **`### {分区标题}`**，标题与 PAGE 明细内 **`####` / `#####`** **逐字对齐**（**勿**自拟另一套分区名）。
- 每分区固定三 bullet：**结构与控件**、**交互与跳转**、**涉及接口**（接口 **只** 写 **`API-*` 编号**，**不**写请求/响应字段）。
- **局部自定义UI组件分区**：**结构与控件** / **交互与跳转** **禁止**复述 `ui/COMP-*` 中的 **UI 状态矩阵**（loading/empty/error/edit 等）；首次出现处 **一行加粗** `**{组件名}（详见 ui/COMP-*.md）**` 即可。
- **加载 / 空态 / 异常 / 动效（页面级）**：仅写 **非组件内部** 的页面级编排（如首屏并行请求、路由级 overlay、与壳层并行刷新）；**组件分区** 的状态 **以 COMP 为准**。
- **补缺（可选，非全面加厚）**：当 **`ui/PAGE-*.md`** 在该 **`####`** 条目下 **未写清**与本页交付相关的 **页面级** 加载编排 / 弱网兜底 / 静默请求等（**非** COMP 内部态），允许在 **本条「交互与跳转」**内 **补几句**。**仍禁止**：①抄写 **`api/API-*.md` 业务字段表**或粘贴 JSON；②新增或与 **PAGE 明细层级顺序相悖**的自拟 **`###` 分区标题**；③把本节写成 **复述 COMP** 状态矩阵或组件长文。
- **出页**：在 **交互与跳转** 写 **控件级** 触发；**全页汇总** 在 **第 4 节**，与本节 **不矛盾**。
- **桌面端**：**不写**壳侧栏、壳顶栏等 **壳层换页**（与 **第 4 节** 桌面专项一致）。
- **分区内线框（可选）**：结构复杂的 **`###`** 下，可在三 bullet **之前** 再嵌 **小号** ASCII 块，细化该分区；**勿**与整页线框 **矛盾**。
- **局部自定义UI组件（若有）**：首次出现处 **一行加粗** `**{组件名}（详见 ui/COMP-*.md）**`；名称与 **`ui_manifest` §4**、`ui/COMP-*.md` **逐字一致**。

### 4. 页面跳转清单

- **表列（固定）**：**目标页面编号** | **目标页面名称** | **存放路径** | **触发条件** | **跳转类型** | **备注**（后四列含义同模板；**存放路径** 见下条）。
- **存放路径**：取 `ui/PAGE-*.md`（优先）或 `ui_manifest.md` 页面清单中该目标页记录的路径信息，**逐字一致**；若无则写 **无**。
- 目标页须在 `ui_manifest`/`ui/` 已登记 **PAGE-***；**禁止**未立项页。
- 与 **第 3 节**「交互与跳转」**同源核对**；表为 **全页出口**。
- **桌面端**：**仅**主工作区 / 页面内容区控件触发的出页；**不**收录业务壳（顶栏、侧栏、面包屑、壳层 Tab）换页，也**不**把预览壳「规格说明」当成业务跳转；壳由 **⑤** `lny-prd-page/reference.md`「桌面业务壳 PRD」落盘（`pages_prd/_shell/{终端编码}-shell.md`），**勿**在本单页罗列壳跳转。
- **跳转类型**：填该终端/技术栈常用表述（如小程序 `navigateTo`、Web `push`、Tab、外链等）。

### 5. API 交互清单

- **仅**三列索引：接口编号、本页用途一句、触发时机；**不**列请求/响应字段、**不**贴 JSON。
- 与 **第 3 节**「涉及接口」汇总 **一致**；**不**增删未在 `api_spec` 登记的编号。
- 同一接口多处触发：在「触发时机」用 **分号** 并列；过长可改为两列（**接口编号** | **用途与触发**）。
- **估点可数**：有效数据行按 **接口编号去重** 后的条数 = 本页 API 数；无接口时表内一行写 **无**（计 **0**）。**AD/桌面业务页必填本节**（供 BE ①「本页 API 数量档」；典型增删改查通常 0～4 条）。

### 6. Feature 关联清单

- **仅**五列索引：Feature 编号、Feature 名称、关联 AC、本页关联点、来源路径。
- 数据来源为 `feature_spec.md` 与 `feature/FEATURE-*.md`；只收录与本页直接相关的 `FEATURE-*`。
- **关联 AC** 只写该 Feature 中 `关联页面` 含本页的 `AC-*` 编号，不复制 AC 正文；多个编号用逗号分隔。Feature 指向本页的 AC 集合必须与本表反向记录完全一致。
- 若本页暂无关联 Feature，须写 **无**（不可留空）。
- 与第 3 节交互说明、第 5 节 API 清单保持一致（同一业务链路可互相追溯）。

### 7. 数据请求模式（估点信号）

- **仅**短表；**禁止**在本节重抄 `ui/PAGE` 交互/视觉正文或 `api/` 字段表。
- **交互体验 / 视觉细节**：写 **见 `ui/PAGE-*`**（或与 ui 同源枚举），**不**在本文件另写长文。
- **非 AD 业务页（不含 `_shell`）必填 `流程角色`**，用于业务主次与压缩候选，**不参与 hour-v1 工时计分**；AD 页可填 **无** 或同枚举。
- **`API 请求编排类型`判定（相对 §5 去重条数；禁止凭「有多个接口」就选混合）**：
  1. **先看条数硬门槛**：`本页API条数` = `0` 或 `1` → **必须** `单请求或并行`；`=2` → **只允许** `单请求或并行` 或 `串行`（**禁止** `串并行混合`）；`≥3` 才允许考虑 `串并行混合`。
  2. **再看依赖（读 §5「触发时机」与第 3 节涉及接口）**：
     - `单请求或并行`：无请求，或仅 1 个；或 ≥2 个但**彼此无先后依赖**（可同时发起 / 各自独立触发，含「进页并行拉 A+B」）。
     - `串行`：≥2 个，且主路径上存在 **明确先后依赖**（后请求依赖前响应），且**基本无并行扇出**。
     - `串并行混合`：仅当 `≥3` 且**同一主路径**上同时存在「串行依赖」与「并行扇出」（例：先串行鉴权/配置，再并行列表+角标；或并行拉多项后再串行提交）。**两接口页即使有 A→B 再点别的，也不算混合。**
  3. 证据不足时：**偏保守**——两接口无明文依赖 → `单请求或并行`；有明文 A→B → `串行`；**禁止默认 `串并行混合`**。
- 必填行：

| 属性 | 内容 |
|------|------|
| API 请求编排类型 | {单请求或并行 / 串行 / 串并行混合}（判定见上；与 `本页API条数` 门槛一致） |
| 流程角色 | {主流程 / 支线 / 辅助 / 设置；AD 可填 **无**} |
| 关联 FEATURE | {FEATURE-*；无则 **无**} |
| 本页API条数（去重） | {非负整数；**须 = §5 有效接口编号去重行数**；无接口填 **0**} |
| D5弹窗数 | {桌面/AD：**见 `ui/PAGE-*` 基本信息同名栏**（只引用数字，不在此另编清单）；移动端填 **无**} |
