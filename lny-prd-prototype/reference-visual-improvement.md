# 视觉质量提升闭环

评分只用于定位问题。原型任务必须继续执行真实渲染、诊断、修改和复验，直到页面达到产品目标与项目视觉档案要求。

## 修复顺序

每轮只处理最影响观感的三项，按以下顺序排序。

1. 首屏任务和视觉锚点是否明确，先处理主视觉、主标题、主操作和内容起点。
2. 页面节奏是否成立，处理区块比例、留白、卡片堆叠、固定区和滚动区关系。
3. 视觉语言是否统一，处理颜色语义、字体层级、圆角、边框、阴影、图标粗细。
4. 素材是否支撑品牌，处理主视觉图、纹理、插画、图标和图片裁切。
5. 细节是否精致，处理按钮状态、分隔线、数字对齐、文字截断和触控尺寸。

## 每轮执行

1. 读取项目视觉档案、页面规格和当前 HTML。
2. 真实渲染目标页面并保留截图。
3. 从截图记录三条最高影响问题，每条必须包含位置、现象、原因和修改动作。
4. 直接修改 HTML、CSS 或素材引用，优先复用项目现有资产和 token。
5. 重新渲染，检查截图和交互，确认修改没有破坏规格覆盖。
6. 使用截图差异工具确认修改确实影响了目标区域。若差异为零，继续诊断，不得把评分结果当作修复完成。

## 通过条件

- 首屏主任务在 3 秒内可识别。
- 页面存在明确的主次层级，关键操作、辅助信息和装饰不会等权竞争。
- 同一终端的页面共享颜色、字体、圆角、阴影和图标语言。
- 关键品牌元素在 HTML 中有可追溯的实现路径。
- 视觉评分报告中的 implementationScore、visualReadiness 和人工审美结论分别记录。
- 自动评分通过不代表视觉完成。若截图仍显得普通、模板化或与视觉档案偏离，继续修复。

## 交付记录

在 `prototypes/.design-decisions/PAGE-*.md` 追加每轮的截图路径、三条问题、修改动作和复验结果。只记录影响当前页面的决策，不复制整份评分报告。
