# 迭代台账与落盘模板

执行 `/lny-prd-iter` 时 Read 本节后落盘。SKILL 只定边界与步骤。

## 输入变量

```yaml
版本号: v1.1.0
版本名称:    # 可选；给人看的短名。无则用迭代内容简述
新增页面: [PAGE-MP-004]
修改页面: [PAGE-MP-001]
废弃页面: [PAGE-MP-003]
新增接口: [API-MP-010]
修改接口: [API-MP-002]
废弃接口: [API-MP-003]
新增功能: [FEATURE-010]
修改功能: [FEATURE-003]
废弃功能: [FEATURE-001]
变更形态:  # 可省略；按条覆盖。默认：新增→新建，修改→修改，废弃→废弃删除；用户明示可复用→复制扩展
存量数据影响: 无  # 可省略，默认无。取值：无 / 需迁移 / 需备份或回滚预案。禁止 DDL
```

功能编号用 `FEATURE-{三位序号}`；历史 `FEATURE-MP-001` 可出现在输入中。列表项可省略。

用户可给 YAML 或自然语言。一句意图可拆多行（例：「首页改版并加登录接口」→ 修改 PAGE + 新增 API）。ID 已知则填入；未知则 `ID` 写 `待确认`、`摘要` 写原意、`委派步` 仍标明。关键词「下线/废弃/删除/不再使用」且对象为页面/接口/功能 → 操作列 **废弃**（不删文件）。禁止模糊的 `UI变更: 描述文字`。

## 统一台账表

三类 `*_changes.md` 同表（无变更时保留表头，正文写 **无**）：

```markdown
# {UI|API|Feature} 变更台账 - {版本号}

| ID | 操作 | 变更形态 | 存量数据影响 | 摘要 | 委派步 | pages_prd目标路径 | 状态 |
|----|------|----------|--------------|------|--------|-------------------|------|
| PAGE-MP-004 | 新增 | 新建 | 无 | {一句话} | ② | versions/{v}/pages_prd/pages/index/PAGE-MP-004.md | 待② |
| PAGE-MP-001 | 修改 | 修改 | 无 | {一句话} | ② | versions/{v}/pages_prd/pages/index/PAGE-MP-001.md | 待② |
| PAGE-MP-003 | 废弃 | 废弃删除 | 需备份或回滚预案 | {一句话} | ② | 无需单页 PRD | 待② |
| API-MP-010 | 新增 | 复制扩展 | 无 | {一句话} | ③ | — | 待③ |
| FEATURE-010 | 修改 | 修改 | 需迁移 | {一句话} | ④ | — | 待④ |
```

| 列 | 取值 |
|----|------|
| 操作 | `新增` / `修改` / `废弃` |
| 变更形态 | `新建` / `复制扩展` / `修改` / `废弃删除`（必填；复制扩展 = 以既有为底少改；默认随操作；用户明示可复用时用 `复制扩展`） |
| 存量数据影响 | `无` / `需迁移` / `需备份或回滚预案`（必填；禁止 DDL/表名） |
| 状态 | `待②` / `待③` / `待④` / `待⑤` / `已完成`（本步只初始化） |
| pages_prd目标路径 | 仅新增/修改页面填写（规则见 `lny-prd-page`）；废弃页面填 `无需单页 PRD` 或 `—`；api/feature 填 `—` |

同一页面新增或修改：一行覆盖 ② 与 ⑤；`pages_prd目标路径` 必填；状态可写 `待②/待⑤`。

## `eval_signals.md`

必建。从三类台账汇总，不计 SP，禁止长文。

```markdown
# 迭代估点信号 - {版本号}

> 阶段 1 只采信号、不计故事点。明细以三类 `*_changes.md` 为准；本文件为汇总。

## 1. 变更形态统计

| 变更形态 | UI | API | Feature | 合计 |
|----------|----|-----|---------|------|
| 新建 | n | n | n | n |
| 复制扩展 | n | n | n | n |
| 修改 | n | n | n | n |
| 废弃删除 | n | n | n | n |

## 2. 存量数据影响统计

| 存量数据影响 | UI | API | Feature | 合计 |
|--------------|----|-----|---------|------|
| 无 | n | n | n | n |
| 需迁移 | n | n | n | n |
| 需备份或回滚预案 | n | n | n | n |

## 3. 需关注条目（存量 ≠ 无）

| ID | 台账 | 变更形态 | 存量数据影响 | 摘要 |
|----|------|----------|--------------|------|
| {FEATURE-010} | feature | 修改 | 需迁移 | {一句话} |
| {无则一行写无} | — | — | — | 无 |
```

## `iteration_notes.md` 开篇

```markdown
# 迭代摘要 - {版本号}

## 版本名称
{版本名称；无则用迭代内容简述}

## 版本目标
{迭代内容简述}

## 变更统计
- 页面：新增 n / 修改 n / 废弃 n
- 接口：新增 n / 修改 n / 废弃 n
- 功能：新增 n / 修改 n / 废弃 n
- 估点信号：见同目录 `eval_signals.md`（不计点）

## 委派顺序
1. `/lny-prd-ui`（②）— {待办 PAGE 摘要}
2. `/lny-prd-api`（③）— {待办 API 摘要}
3. `/lny-prd-feature`（④）— {待办 FEATURE 摘要}
4. `/lny-prd-page`（⑤）— {待办 pages_prd 路径列表}
5. `/lny-prd-prototype`（⑥）— 有新增/修改页面时必做；仅 API/Feature 变更时可选
6. `/lny-prd-check`（⑦）— 须用户明确要求检查，不随「继续」自动跑
7. `/lny-prd-sp`（⑨）— 台账与规格就绪后按本版本估点（可选）
```

文末流水过滤见 `lny-prd-master/SKILL.md` §1.1.1 / §1.1.2。⑧ 只写开篇；②③④⑤ 按序追加；⑥⑦⑨ 不维护流水。

## 版本号校验

1. 格式 `v{主}.{次}.{修订}`
2. 须 **>** `versions/` 下当前最新（与变更记录冲突时以 `versions/` 为准并说明）
3. 合理递增：v1.2.3 → v1.2.4 / v1.3.0 / v2.0.0；跳跃允许但警告；递减报错
