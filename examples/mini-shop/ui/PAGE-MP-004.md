## 2. 页面层级及布局描述

### 2.1 移动端结构（操控形态=移动端时填写）

#### │ L0 系统层
- 顶栏模式 **标准**（状态栏背景不透明）；真机预览状态栏固定顶、不随页滚，电量/信号靠右；页内可点控件避让右上胶囊，禁止在胶囊区放按钮；圆角/曲面屏左右下及四角留安全距；无 TabBar

#### │ L1 固定导航层
- 无 TabBar；页内顶栏左侧返回、标题「到货提醒」，右侧避让胶囊
- 主操作条「取消」「提交」贴底固定、不随 L2 滚动

#### │ L2 主体滚动层
- 分区头「填写资料」；其下表单字段自上而下滚动

#### │ L3 模块容器层
- 表单块，每项独立成行，输入右侧留安全距：
  - 「联系人」「联系电话」
  - 「通知方式」标签单选
  - 「提醒优先级」五步滑动条（低～高）
  - 「可接受溢价」无极滑动条（显示当前百分比）
  - 「期望规格」下拉选择器
  - 「期望到货日期」点开后底半屏年-月-日三级联动
  - 「收货地区」点开后底半屏省-市-区三级联动
  - 「包装参考」图片/视频单张上传，可预览、点「更换」替换
  - 「现场照片」图片/视频多张上传，可「添加」、可「删除」
  - 「到货凭证」文件上传，显示文件名
  - 允许店铺联系我；「备注」

#### │ L4 内容元素层
- 通知方式为标签单选（微信通知 / 短信），选中右上对号角标；开关独立成行；滑动条有刻度或当前值；可点元素无下划线，按下有反馈，热区 ≥44px

#### │ L5 浮层与反馈层（如有）
- 日期、省市区为底半屏，点遮罩关闭，显隐过渡而非瞬切；半屏内「取消」「确定」
- 校验失败、提交成功 Toast；取消直接回详情，不确认

### 2.3 交互体验设计（必填）

- **观感与舒适**：标准顶栏标明「到货提醒」；字段一列排开、组间留空防误触；输入框右侧留安全距；主按钮贴底，避免滑到页尾才找提交。
- **动效与过渡**：日期/地区底半屏自下向上滑入（中），遮罩淡入；Toast 淡入（快）。
- **微反馈**：提交中可禁用按钮；缺必填居中 Toast「请填写联系人与电话」；成功 Toast「已登记到货提醒」；开关、标签、滑动条、上传按下有反馈。
- **收纳与浮层**：完整登记用整页；日期与省市区收进底半屏三级联动，避免页内三个下拉挤在一起；取消直接回详情，不二次确认。
