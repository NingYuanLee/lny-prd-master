## 1. 项目概述
### 1.1 产品定位与愿景
最小夹具：用户浏览商品列表、查看详情，并可登记到货提醒；管理员在后台查询、弹窗维护并打开整页表单。用于对照 LNY-PRD 粒度，不是完整电商。

### 1.2 用户故事

| 故事编号 | 用户类型 | 用户画像 | 用户故事 | 关联 FEATURE / 框架承接 |
|----------|----------|----------|----------|-------------------------|
| STORY-001 | 买家 | 小程序内浏览商品的消费者 | 我要在首页看到推荐、在列表搜索筛选并进入详情，以便看清可买商品 | FEATURE-001 |
| STORY-002 | 运营 | 后台维护商品的运营人员 | 我要在后台筛选列表、弹窗查看/编辑，并打开整页表单维护商品 | FEATURE-002 |
| STORY-003 | 买家 | 小程序内浏览商品的消费者 | 我要在详情后登记到货提醒，以便商品到货时被通知 | FEATURE-003 |

### 1.3 竞品分析
无。本目录仅为技能包回归样例。

### 1.4 成功怎么算
买家能从首页看到推荐、在列表搜索筛选并打开详情；缺货场景可登记到货提醒。运营能在后台筛选列表、用弹窗查看/编辑，并用整页表单保存商品。

### 1.5 明确不做
- 下单、支付、登录（框架承接）
- 自拟埋点方案

## 2. 通用规范与阅读指南

### 2.1 编号规则与追溯（速查）

| 类型 | 编号规则 | 说明 |
|------|----------|------|
| 终端 | MP 小程序 / AD 管理后台 | 终端清单见 §4 |
| 页面 | `PAGE-{终端类型编码}-{三位序号}` | 如 `PAGE-MP-001` |
| 接口 | `API-{终端类型编码}-{三位序号}` | 如 `API-MP-001` |
| 第三方接口 | `EXT-{三位序号}` | 如 `EXT-001` |
| 组件 | `COMP-{三位序号}` | 如 `COMP-001` |
| 功能 | `FEATURE-{三位序号}` | 如 `FEATURE-001` |
| 业务模块 | `MODULE-{三位序号}` | 模块改名时编号不变 |
| 用户故事 | `STORY-{三位序号}` | 与 FEATURE 可为 N:M |

**追溯链**：`STORY → FEATURE → AC（验收标准）→ PAGE → API`。任何需求都能沿这条链追到页面和接口；断链即规格不完整。路由/路径约定见 `ui_manifest.md` §3。

### 2.2 文档地图（入口清单）

| 文档 | 用途 |
|------|------|
| 本文件 `main_spec.md` | 产品全貌、终端（§4）、三大索引（§5/§6/§7） |
| `ui_manifest.md` + `ui/` | 页面/组件清单与详述（布局、状态、组件） |
| `api_spec.md` + `api/` | 接口需求（业务语义，非技术契约） |
| `feature_spec.md` + `feature/` | 功能规格（目标、规则、AC、时序/流程图） |
| `versions/{v}/pages_prd/` | 单页 PRD（逐页数据来源、跳转、API 交互） |
| `prototypes/` | 静态原型（仅视觉参考，见 §2.6） |

### 2.3 开发侧阅读顺序

- **BE**：`main_spec`（§1 概述 / §4 终端 / §6 API 索引）→ `api_spec` → `api/` → `feature/`（AC、规则、时序图）
- **FE**：`main_spec`（§1 / §4 / §5 UI 索引）→ `ui_manifest` → `ui/`（先 COMP 再 PAGE）→ `api/` 全局层 → `pages_prd` 装配

### 2.4 技术选型决策点（开发侧自定）

本套 PRD 只写「产品要什么」，不写「怎么实现」。以下由开发侧在实现阶段自行决定：框架/语言、数据库与 DDL、API 的 path/HTTP 方法/JSON 字段/响应 code、缓存与鉴权实现、路由落地。

### 2.5 验收标准与测试约定

Feature 的 AC 是自然语言验收标准，不是可执行测试。开发侧需把每条 AC 翻译为测试用例，并保留 AC 编号 ↔ 测试的映射（如 `AC-3 → T-FEATURE-001-3`），便于回归对照。

### 2.6 原型定位

`prototypes/` 是静态展示品，仅作视觉/交互参考，不是可上线前端工程；没有路由、状态管理、接口联调。开发侧应另起工程实现，不得在原型 HTML 上继续开发。

### 2.7 非需求文件（开发侧可忽略）

`versions/{v}/` 下的 `sp_report.md`（估点）、`delivery_scope.md`（评审决议）、`eval_signals.md`（迭代估点信号）、`*_changes.md`（变更台账）、`iteration_notes.md`（过程流水）是产品管理过程文件，编码实现无需阅读。
