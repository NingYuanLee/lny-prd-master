# 产品发现与假设验证

本模块由总控按需调用，面向单一产品经理提供轻量但完整的 Discovery 能力。它不要求用户先准备完整研究方案，也不把普通信息缺失当作阻塞。总控规则见 [`../lny-prd-master/SKILL.md`](../lny-prd-master/SKILL.md)。

## 输入

- 用户自然语言、聊天记录、会议纪要、访谈记录和反馈
- 竞品链接、截图、已有 PRD、业务数据和客服记录
- 当前 `product_workspace.md`、`evidence_log.md`、`main_spec.md` 和相关 Feature

## 输出

- 更新 `evidence_log.md`，记录事实、推断、假设、来源、置信度、验证方式和结果
- 按需更新 `product_workspace.md` 的当前问题、关键风险和下一动作
- 对已验证且改变产品事实的内容，回流 `main_spec.md`、Feature、UI、API、Page 或版本台账
- 对未验证内容保留为假设，不写成已批准事实

## 执行规则

1. 先区分用户原话、可核对数据、模型推断和默认假设。
2. 从证据中提炼用户问题、目标、机会和约束，不直接把功能请求当成问题结论。
3. 为影响最大的假设选择最小验证动作，优先使用访谈、原型、数据观察或小实验。
4. 记录验证结果和对方案的影响。
5. 只有用户明确要求或证据足够改变产品事实时，才回写正式规格。

## 询问边界

只有当两种解释会导致不同产品目标、范围或不可逆决策时才向用户询问。普通画像、页面结构、文案和验证形式由模型选择并记录假设。

## 收尾

回报已提炼的问题、关键假设、证据状态、验证动作和受影响的下游步骤。需要回流时交总控按影响范围继续推进。
