# 视觉质量提升闭环

评分只用于定位问题。原型任务必须继续执行真实渲染、实际截图查看、证据化自评、修改和复验，直到页面达到 [`reference-visual-self-review.md`](reference-visual-self-review.md) 的通过门槛。模型不能把“评分通过”当作自己的视觉判断。

重设计时，若主要视觉问题来自上游指定的表现形式，按[重设计选型](../lny-prd-ui/reference-design-choices.md)做可逆试验，复核原先的形式是否仍服务目标。

## 修复顺序

先用[设计选型](../lny-prd-ui/reference-design-choices.md)判断问题在信息顺序、构图、素材还是局部样式。每轮选最影响当前任务的问题，以下是排查线索。

1. 首屏任务和视觉锚点是否明确，先处理主视觉、主标题、主操作和内容起点。
2. 页面节奏是否成立，处理区块比例、留白、卡片堆叠、固定区和滚动区关系。
3. 视觉语言是否统一，处理颜色语义、字体层级、圆角、边框、阴影、图标粗细。
4. 素材是否支撑品牌，处理主视觉图、纹理、插画、图标和图片裁切。
5. 细节是否精致，处理按钮状态、分隔线、数字对齐、文字截断和触控尺寸。

## 首次交付前的走查

首次展示的是作者走查后的版本。对决定体验的页面，打开实际入口和目标视口，先看初始画面，再做一次会改变构图的真实操作。滚动页滚到上一块刚离开屏幕的位置，固定栏、下方内容和新露出的操作同屏时再看一次；工作台则可打开常用抽屉或切换到有数据的状态。只检查与该页有关的场景。

脱离设计说明读画面：第一眼落在哪里，第二眼能否找到要做的事？分组是否仍然清楚？代表性长标题是否压住图片主体或操作，示例内容是否与当前项目相符？若自动检查通过但这些观察暴露了问题，把影响最大的一处直接改进 HTML。在同一内容、尺寸和滚动位置对照，较差则撤回。小到色差、阴影，大到取消标题或重排首页，都由观察决定。无实质问题可结束；遇到资料冲突影响业务含义时，只询问该项，其他可逆判断继续完成。

沿用已有记录写下具体可复核的结果，例如“滚过摘要后仍能看出筛选栏对应哪张表”。未实际看到渲染结果时注明视觉走查未验证。无需将备选稿或内部自问清单交给用户。

## 每轮执行

1. 读取项目视觉档案、页面规格和当前 HTML。
2. 真实渲染目标页面并保留截图。
3. 从截图记录有证据的关键问题，每条必须包含位置、现象、原因和修改动作。
4. 直接修改 HTML、CSS 或素材引用，优先复用项目现有资产和 token。
5. 重新渲染，检查截图和交互，确认修改没有破坏规格覆盖。
6. 使用截图差异工具确认修改确实影响了目标区域。若差异为零，继续诊断，不得把评分结果当作修复完成。

## 通过条件

- 在目标视口检查主任务所需的信息和操作是否容易找到；报告可见内容及操作路径。只有实际计时的用户测试才能报告识别用时。
- 页面存在明确的主次层级，关键操作、辅助信息和装饰不会等权竞争。
- 同一终端的页面共享颜色、字体、圆角、阴影和图标语言。
- 关键品牌元素在 HTML 中有可追溯的实现路径。
- 视觉评分报告中的 implementationScore、visualReadiness 与作者对实际截图的观察分别记录。
- 自动评分通过不代表视觉完成。若截图仍显得普通、模板化或与项目任务和设计判断不符，继续修复。
- 视觉自评协议通过，且每个低于 2 分的维度都有修改动作或可复核的保留理由。
