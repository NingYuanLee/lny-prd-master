# 演示级高保真协议

单页 `PAGE-*.html` 是可直接交给他人演示的产品界面。实现完成后，打开业务页即可看到完整的默认状态、可信内容和可操作反馈。规格、状态矩阵、设计决策和验收说明写在外部文件或壳层中，不写进业务页的可见区域。

## 可见内容规则

- 可见文案只服务于用户任务、产品导航、字段、状态反馈和操作结果。禁止出现“示例”“演示”“原型”“占位”“测试数据”“测试用户”“模拟数据”“待补充”“待接入”“TODO”“Lorem ipsum”“placeholder”“mock data”“Item 1”“某某”等开发或草稿词。
- 不把 PAGE 章节名、COMP 编号、API 编号、实现说明、验收提示和设计解释渲染成业务标题、卡片或说明段落。
- 默认态必须有完整内容。列表、表格、卡片和图表使用同一业务域内彼此关联的名称、编号、金额、时间、状态和数量，长度有变化，格式符合真实产品习惯。
- 数据关系要自洽。金额与数量、状态与操作、时间与排序、头像与姓名、统计数字与明细之间不能互相矛盾。跨页面复用同一对象时沿用相同的名称、编号和状态。
- 空态、加载态和失败态只在组件状态要求时出现。空态要有用户能理解的产品文案和下一步操作，失败态要有恢复动作，禁止用“数据将在这里展示”等说明性句子填充界面。
- 关键图片优先使用项目本地素材。没有素材时使用与主题一致的本地 CSS、SVG 或图形化视觉处理，禁止灰色矩形配“图片占位”文字，也禁止依赖不可控的远程图片。

## 版式与交付规则

- 业务页首屏必须有明确主任务、视觉锚点和真实内容密度，禁止只保留顶栏、空表、三张等宽卡片或一排无内容按钮。
- 业务页的默认路径、主要按钮、筛选、分页、弹层和反馈都按真实用户路径可操作。状态演示控件只放在原型壳层。
- `prototypes/{终端}/PAGE-*.html` 是干净演示面。`index.html` 和壳层可以显示规格说明、状态演示和技能标注，但这些内容不能通过 iframe 或共享脚本注入业务页。
- 交付前直接打开每个业务页做一次桌面和移动端渲染检查，检查首屏内容、长文案、图片比例、滚动、操作反馈和无开发痕迹。截图和评分用于定位问题，不能替代人工观看。

## 内容自检

逐页确认以下事实后再交付。

- 页面中没有草稿词、实现词、规格编号或解释性段落。
- 默认态的关键字段来自同一业务域，数据关系、格式和状态相互一致。
- 至少有一处长名称、一处较长状态或说明、一处真实格式的时间、金额或编号，验证布局不会只适配短占位文本。
- 关键视觉元素有本地素材或可交付的本地视觉实现。
- 页面独立打开时不需要阅读规格说明才能理解主要任务。
