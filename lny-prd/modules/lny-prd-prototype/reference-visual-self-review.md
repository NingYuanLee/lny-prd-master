# 原型视觉自评协议

本协议用于让执行原型的 Agent 自己判断页面是否达到可交付标准。评分器只提供结构和渲染信号，不能替代本协议。没有实际查看截图时，不得写“视觉自评通过”。

## 必须查看的证据

每个目标页面至少查看以下截图：

1. 初始状态首屏截图。
2. 一次会改变构图的真实操作后的截图。优先选择滚动、展开、筛选、打开抽屉或切换状态。
3. 页面支持的另一种目标视口截图。移动端查看滚动和固定栏，桌面端查看对齐和信息密度。

截图必须来自实际 HTML 渲染。模型应使用可用的图像查看能力打开截图，不能只读取 HTML、评分 JSON 或截图文件名。

## 十项评分

每项 0～2 分。评分前必须先回答对应的观察问题，并在记录中写出截图位置和可见证据。不能只写“层次清楚”“留白合理”这类结论词。

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 首屏任务 | 看不出页面要完成什么 | 能猜到任务，但主入口不突出 | 第一眼能识别主任务和下一步 |
| 信息层级 | 内容等权或主次混乱 | 有主次，但竞争仍明显 | 主标题、主操作、辅助信息层级清楚 |
| 间距留白 | 间距随机、拥挤或浪费空间 | 有基本节奏，局部挤压或断裂 | 内外间距有层级，留白服务阅读和操作 |
| 布局与对齐 | 溢出、错位或关键内容被遮挡 | 基本稳定，局部对齐需修 | 目标视口内结构稳定，关键列和操作对齐 |
| UI 组件 | 控件像默认拼接，状态或热区缺失 | 可用，但层级、尺寸或状态不稳 | 控件形态、热区、层级和状态都服务任务 |
| 文字与素材 | 文案难读、截断或素材破坏理解 | 可读，但长度或裁切有瑕疵 | 代表性长文案、图片比例和对比度都成立 |
| 风格语言 | 样式像拼接模板或语义混乱 | 风格大体一致 | 色彩、边界、圆角、阴影和图标形成统一风格 |
| 视觉锚点 | 没有记忆点或装饰抢过任务 | 有焦点，但品牌或内容关联弱 | 主视觉锚点明确且支撑页面任务 |
| 状态与反馈 | 操作后无反馈或状态难辨 | 有反馈，但恢复路径弱 | 状态变化、反馈和恢复动作清楚 |
| 跨视口表现 | 另一视口无法完成任务 | 可完成，但密度或滚动明显受损 | 两种目标视口都保持任务、层级和可读性 |

## 把名词转成观察问题

| 维度 | 必须回答的问题 | 常见失败证据 |
|---|---|---|
| 首屏任务 | 不读说明时，第一眼能说出用户要完成什么吗？主操作在首屏哪里？ | 第一眼落在装饰、空白或次要卡片上 |
| 信息层级 | 用户能按“先看什么、再看什么、最后操作什么”阅读吗？主操作是否比次要操作更强？ | 标题、标签、按钮和卡片都一样醒目 |
| 间距留白 | 哪些间距表示同组，哪些间距表示换组？有没有一块空白只是因为布局没收紧？ | 组内比组间更松，区块之间出现随机大洞 |
| 布局与对齐 | 关键标题、内容、图片和操作是否沿着可解释的边线对齐？目标视口有没有裁切或横向溢出？ | 元素边线错开、按钮被挤出、表格列漂移 |
| UI 组件 | 按钮、输入、标签、卡片和导航是否一眼能识别用途？按下、禁用、加载、空态和失败态是否有可见变化？ | 组件只像静态装饰，状态靠文字解释 |
| 文字与素材 | 长标题、数字、辅助文案和图片放入后仍然可读吗？图片裁切有没有破坏主体？ | 文案截断、数字不对齐、图片主体被切掉 |
| 风格语言 | 能否用三条具体规则描述页面风格，并在不同区块看到同样规则？ | 每个区块像来自不同模板，颜色和边界语义漂移 |
| 视觉锚点 | 第一视觉焦点是什么？它为什么应该先被看到？第二焦点是否把人带向主任务？ | 多个强色、插画、徽章或 CTA 抢同一注意力 |
| 状态与反馈 | 做完关键操作后，用户能从画面看出发生了什么、下一步是什么、如何恢复吗？ | 点击后只有颜色闪动，或错误状态没有恢复动作 |
| 跨视口表现 | 在每个目标视口完成同一主任务时，信息顺序和操作热区是否仍成立？ | 窄屏变成挤压桌面版，固定栏遮住内容 |

每项都要用一句具体观察替代空泛结论，例如“首屏第一眼落在右侧橙色促销卡，主操作在第二屏，因此把促销卡降为辅助色并把筛选入口提到首屏”。

## 通过门槛

- 总分至少 16/20。
- 首屏任务、信息层级、布局与对齐、UI 组件、状态与反馈不得为 0 分。
- 每个低于 2 分的维度必须有明确修改动作，或记录为什么该取舍符合页面任务。
- 返修后必须重新查看同一视口、同一数据和同一操作位置，确认问题已经消失。
- 只要仍能指出一个影响主任务的具体视觉问题，就继续修复，不得以评分达标结束。

## 低质模式拦截

以下表现默认视为需要返修的低质信号。只有项目视觉事实或页面任务明确要求时才保留，并在自评记录中说明依据：

- 标题左侧加一条彩色竖线、装饰边框或渐变条作为默认“设计感”。
- 所有区块都套白底圆角卡片，所有操作都做成彩色按钮。
- 首页固定套三张等宽卡片、居中大标题和大面积空白，没有内容任务依据。
- 用大量胶囊标签、彩色徽章、渐变、粗阴影或 emoji 代替真实层级。
- 标题、正文、辅助信息只有字号变化，没有字重、颜色、间距和位置层级。
- 视觉焦点平均分散，首屏同时出现多个同等强度的主色、插图或 CTA。
- 组件只完成静态外观，悬停、按下、禁用、加载、空态或失败态没有一致反馈。
- 通过增加线条、阴影、边框和装饰补救信息结构问题。

自评时必须回答：这个视觉选择服务哪个任务？如果删掉它，用户会损失什么？如果答案只是“更有设计感”，继续返修。

## 记录格式

在 `prototypes/.design-decisions/PAGE-*.md` 追加：

```markdown
## 视觉自评 - {轮次}

- 截图证据：{首屏路径}；{操作后路径}；{另一视口路径}
- 实际查看：是
- 总分：{分数}/16

| 维度 | 分数 | 截图证据 | 修改或保留理由 |
|---|---:|---|---|
| 首屏任务 | 0-2 | {位置与现象} | {动作或理由} |
| 信息层级 | 0-2 | {位置与现象} | {动作或理由} |
| 间距留白 | 0-2 | {位置与现象} | {动作或理由} |
| 布局与对齐 | 0-2 | {位置与现象} | {动作或理由} |
| UI 组件 | 0-2 | {位置与现象} | {动作或理由} |
| 文字与素材 | 0-2 | {位置与现象} | {动作或理由} |
| 风格语言 | 0-2 | {位置与现象} | {动作或理由} |
| 视觉锚点 | 0-2 | {位置与现象} | {动作或理由} |
| 状态与反馈 | 0-2 | {位置与现象} | {动作或理由} |
| 跨视口表现 | 0-2 | {位置与现象} | {动作或理由} |

- 结论：通过 / 继续返修
- 复验：{返修后再次查看的证据}
```

“实际查看：是”只能在模型真的打开并观察截图后填写。评分器通过、截图差异非零或 HTML 结构完整，都不能单独构成通过结论。
