# ui/COMP-*.md 模板
```markdown
# {组件名称} 组件详述

## 1. 基本信息

| 属性 | 内容 |
|------|------|
| 组件名称 | {组件名称} |
| 组件编号 | {COMP-001} |
| 设计前提 | {相同结构+交互+状态的多页复用 / 独立状态机 / 两者兼有} |
| 独立视觉状态机 | {是 / 否；否时通常并回 PAGE 分区} |
| 适用终端 | {MP / APP / H5 / PC / AD，可多选} |
| 覆盖页面 | {PAGE-*.md 列表；仅多态暂未复用时可为单页} |
| 来源 | {新建 / 沉淀复用 / 既有组件升级} |

## 2. 用途与范围

- **用途**：{一句话说明解决的问题}
- **判定依据**：{列出至少两个使用页面及其相同的结构、交互和状态契约，或说明该组件为何拥有独立状态机和独立复用价值}
- **适用场景**：{在哪些页面分区复用}
- **边界与排除项**：{哪些场景不适用}
- **单职责**：本组件自洽管理自己的 UI 状态。多块视觉分区只有在共享同一状态机且视觉相邻时才放在一个 COMP 内。仅因语义相近、字段相同或外观相似而合并的页面区块不属于同一 COMP。
- **抽象层级**：默认保持一层组件。只有父子区块各自拥有独立状态机，或父子区块都被独立复用时，才允许嵌套；纯布局容器、标题、图标、单个按钮和一次性局部区块留在父组件或 PAGE 内。

## 3. 结构与交互

- **结构分层**：{容器、内容区、操作区等}
- **交互表现**：{上游既定操作触发后，组件如何展开、折叠、半屏或弹窗；不得补设业务条件}
- **动效与微反馈**：{按下/悬停/焦点；开闭过渡；成功/失败反馈；无则写 **无** 并说明为何瞬切可接受}
- **状态机与区块联动（如有）**：{状态枚举、转移条件、相邻子区如何随状态联动；无则写 **无**}
- **状态切换入口**：{页内 TabBar/Tabs/SegmentedControl/按钮组/无（单态）；仅产品页内语义，禁止写预览壳状态演示、postMessage 等；无页内入口时由 `$lny-prd` 状态演示推断}

### 3.1 跨页视觉复用契约

- **继承的项目视觉事实**：{引用 `ui/visual/visual-profile.md` 与 `tokens.json` 中适用的基础语言}
- **组件固定表现**：{跨页必须保持的结构层级、边界语言、按钮层级、图标语言和状态语言；不写 CSS 参数}
- **允许的局部变化**：{内容密度、文案长度、图片比例或终端适配；无则写无}
- **禁止的局部变化**：{不得在 PAGE 中改写的组件视觉表现}

### 3.2 复用边界

- **可以复用**：结构层级、触发方式、可见状态、状态转移、操作结果和主要反馈都一致的 UI 单元。
- **分别保留**：页面类型、阅读任务、信息密度、操作路径或状态机不同的区块，即使名称、字段或业务语义相近。
- **不建子组件**：只负责排版、间距、标题、图标、单个按钮或一次性组合的区块。
- **合并检查**：如果删除子组件文件后父组件仍能清楚描述自身结构和状态，且子组件没有第二个使用页面，应把它并回父组件或 PAGE。

## 4. UI 状态矩阵（必填）

| 状态 | 触发条件 | 展示要点 | 可执行操作 |
|------|----------|----------|------------|
| {仅填写本组件实际可触发的状态；无此状态必须删行} | {真实触发条件} | {必须能在页面中辨认的视觉差异} | {真实可执行操作；无则写无} |

状态矩阵只定义可见 UI 差异，不定义业务状态机。不要整段保留 `loading / empty / error / edit / default`；至少保留真实默认态。`loading`、`empty`、`error` 只在上游规格已有对应情形时填写；`edit`、`disabled`、`pending` 等只描述既定状态的视觉实现，触发条件引用上游事实而不在此重定义。状态演示壳层会按本表逐字生成，遗漏或泛化都会被原型验收拦截。

- **默认态 / 交互态**：{按下 / 焦点 / disabled / 悬停（桌面增强）；须能脱离 hover 辨认；无则写 **无**}
```
