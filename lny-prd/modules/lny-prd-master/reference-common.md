# LNY-PRD 公共规则

这些规则只在子技能实际写入 PRD 产物时读取。

## 正式落点

- 根规范：`main_spec.md`、`ui_manifest.md`、`api_spec.md`、`feature_spec.md`
- 工作源：`pages_prd/{终端}/PAGE-*.md`
- 当前原型：`prototypes/`
- 版本记录：`versions/{版本}/`

禁止创建 `versions/{版本}/prototypes/`、根规范镜像或备用副本。

## 版本与记录

- 立项只创建 `v1.0.0` 和初始变更记录。
- 新版本和新的变更记录行只由 ⑩ 创建。
- ②～⑨ 不新增变更记录行。
- 根四规范发生业务变化时，在当前版本 `iteration_notes.md` 追加业务摘要。
- 纯文档修复、台账状态、评审和检查报告不写业务流水。
- 当前版本默认取 `versions/` 最大 semver，显式版本必须已存在。

## 台账

状态只能是单值。页面为 `待② → 待⑤ → 已完成`，API 为 `待③ → 已完成`，Feature 为 `待④ → 已完成`。只有产物和自检都通过后才推进。

## 写入边界

每个正式文件只有一个写者。共享索引、台账、流水、壳层、入口、范围、SP 报告和门禁结论由主 Agent 写。写入前只读取任务所需的参考章节，遇到版本、委派或跨步骤边界时再读取对应 reference。

## 收尾

结束时报告已执行步骤、门禁状态、下一停点和下一份将读取的 `SKILL.md`。缺少产品事实时才停下来询问用户。

## 产物精简规范

- 正式文档只写产品事实、设计决策、状态、规则、追溯关系和验收标准。
- 每个段落先给结论，通常 1～3 句。能用表格表达时不写长段落。
- 删除背景复述、过程日志、技能说明、重复定义、泛泛建议和过程解释。
- 同一事实只保留一个正本，其他位置用编号或文件路径引用。
- 示例只保留一个能说明格式的例子，不复制整套样例。
- 不为显得完整而填充“无”。只有字段会影响实现、检查或追溯时才写。
- 明细优先控制在可快速扫描的长度，复杂规则拆成列表或状态表。
- 对话汇报使用“已完成 / 未完成 / 阻塞 / 下一步”四项，不输出长篇过程复盘。
