# 智能自动推进协议

本协议定义 LNY PRD Workflow 的默认工作方式。它面向单一产品经理，保留完整产品能力，由总控根据输入、项目状态和影响范围自动选择最小必要路径。

## 总原则

- 输入可以是碎片化自然语言、文件、截图、链接、反馈或局部修改意见。
- 能依据上下文合理推断的内容由模型补齐，不要求用户先填写完整表单。
- 模型补齐的内容必须记录为事实、推断、默认假设或待确认项。
- 用户当前明确意图优先于历史表达；已批准事实优先于模型推断。
- 只在事实冲突、范围变化、关键证据缺失或用户明确要求确认时暂停。
- 自动推进按影响范围计算最小依赖闭包，不按固定十步链无条件重跑。
- 完整能力保留在内部模块，默认对话只展示当前决策、风险、产物和下一停点。
- 工具选择优先使用当前宿主已有能力和技能自带脚本。缺少可选依赖时先用 CUA 或静态检查替代，只有目标检查无法完成时才向用户提出安装选择。

## 输入归一化

收到输入后先归一化为以下对象：

| 对象 | 内容 |
|---|---|
| 用户意图 | 新建、补全、修改、演示、检查、评审、估点、迭代或继续 |
| 已确认事实 | 用户明确表达、项目文件、批准结论或可核对资料 |
| 高可信推断 | 不改变产品目标且可由上下文推出的内容 |
| 可逆默认 | 页面、文案、视觉、编号和常规状态等可替换决策 |
| 待确认项 | 影响目标、范围、品牌事实、权限或不可逆决策的缺口 |
| 冲突项 | 用户之间、文件之间或新旧批准事实之间的矛盾 |

不因普通缺字段停止。先用高可信推断和可逆默认继续，并在收尾报告中列出假设。

## 路由算法

1. 读取 PRD 根目录和当前工作版本状态。
2. 识别用户目标与明确范围。
3. 判断是否需要探索讨论。输入明确、证据充分或只是局部修改时跳过；问题模糊、假设冲突、存在多种方案或需要研究验证时进入 Discovery。
4. 形成暂定或已确认的产品决策。
5. 计算当前输入影响的 Story、Feature、API、PAGE、COMP、版本和原型对象。
6. 找出这些对象所需的最小前置产物。
7. 先执行最早责任步骤，再自动推进所有必要下游步骤。
8. 每一步完成后运行该步骤的局部检查，并根据结果决定继续、返修或暂停。
9. 只有用户要求完整检查、正式评审、估点或新版本时，才展开对应的横向门禁和版本流程。

## 典型路径

| 输入目标 | 自动路径 |
|---|---|
| 碎片想法并要求完整方案 | 立项 → 发现补全 → UI/API/Feature/Page → Q-S → 原型 → Q-P |
| 目标不清或多个方向待比较 | 识别意图 → Discovery 探索 → 暂定/已确认决策 → 最小规格链 |
| 只要求可演示原型 | 补齐必要规格 → Q-S → 原型 → Q-P |
| 修改视觉或文案 | 目标 UI/PAGE → 原型 → 局部 Q-P |
| 修改 API 字段 | API → 受影响 Feature/UI/PAGE → Q-S → 受影响原型 → Q-P |
| 修改业务规则 | Feature → 关联 API/UI/PAGE → Q-S → 原型 → Q-P |
| 用户说“继续” | 从最早未完成且与当前目标相关的责任步骤恢复 |
| 要求估点 | 读取已确认范围 → 产品链门禁 → SP；不重画无关页面 |
| 要求新版本 | 核验上版终态 → 创建版本台账 → 按变更影响委派 |

## 停止条件

仅在以下情况暂停并向用户提出最少问题：

- 产品目标或用户明确意图存在冲突。
- 需要新增、删除或改变不可逆产品范围。
- 关键品牌资产、合规事实、权限策略或业务规则无法推断。
- 评审、交付范围或批准快照需要产品负责人确认。
- 继续推进会把未经确认的推断写成正式批准事实。

一次暂停集中列出造成分歧的事项。普通布局、字段组织、页面骨架、视觉方向、状态文案、编号和内部文件拆分由模型自行决定。

## 事实与假设记录

项目存在以下文件时优先维护，缺失时按需创建：

- `product_workspace.md`：面向 PM 的当前状态、关键决策、风险、假设和下一动作。
- `evidence_log.md`：事实来源、推断、假设、验证方式和结果。
- `learning_log.md`：发布后反馈、指标结果、复盘结论和下一轮变化。

这些文件是工作台和决策记录，不替代 `main_spec.md`、UI、API、Feature、Page 或版本批准文件中的事实正本。

## 仓库共享边界

项目位于代码库或多人协作目录时，读取 [`reference-repository-sharing.md`](reference-repository-sharing.md)。正式产品事实、评审依据和需要复现的原型按 `shared-required` 处理；截图、缓存、临时脚本、机器路径和敏感材料按 `local-only` 处理；视觉决策和脱敏调研材料按协作需要选择 `shared-optional`。交付前清理本地临时文件，检查共享文件不含密钥、个人信息和绝对路径。

## 对话收尾

默认只回报：

1. 已完成的目标和产物。
2. 自动采用的关键假设。
3. 仍需确认的冲突或风险。
4. 自动选择的下一动作。

完整检查表、模块明细和版本证据继续落盘，但不要求 PM 在每一步手动触发。
