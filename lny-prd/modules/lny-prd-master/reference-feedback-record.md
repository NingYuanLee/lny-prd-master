# 原型反馈记录

原型反馈记录服务于当前版本的快速修订，不创建新版本，也不替代 `iteration_notes.md`。每条记录说明产品反馈如何落到正本和原型，便于检查是否漏改。

```markdown
## FB-{三位序号} {简短标题}

- 日期：YYYY-MM-DD
- 来源：原型反馈
- 反馈原文：{产品经理原话}
- 变更类别：A 视觉微调 / B 交互表现 / C 页面结构 / D 产品事实
- 影响判断：{研发实现是否会改变行为、结构、数据契约或验收结果}
- 事实正本：{无 / main_spec.md / ui/PAGE-* / api/API-* / feature/FEATURE-* / 其它}
- 修改文件：{实际路径列表}
- 修改前截图：{路径}
- 修改后截图：{路径}
- 检查范围：{实际执行的检查}
- 结果：完成 / 升级处理 / 待产品决策
- 遗留问题：{无或具体问题}
```

## 记录规则

- 会影响后续判断的 A 类视觉取舍记录反馈和前后截图。单个错字、间距、颜色、裁切或对齐修正可以不单独建记录。
- B～D 类必须写事实正本。没有正本时先补正本，再改原型。
- “修改文件”只列实际写入路径，不写计划路径。
- “完成”必须有对应检查结果。检查未执行时写“待验证”。
