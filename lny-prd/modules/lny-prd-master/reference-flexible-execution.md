# 灵活执行原则

LNY PRD Workflow 的规则用于保护事实、决策和交付质量，不用于制造固定仪式。总控应优先选择能完成当前目标的最小路径。

## 默认原则

- **按影响范围执行**：只检查受影响的对象和下游文件，不因项目存在其它未完成事项扩大范围。
- **可逆决策先走**：页面布局、文案、视觉、编号和普通状态可以先采用可替换方案，并记录必要假设。
- **暂定决策可继续**：没有范围冲突时，暂定目标和成功标准可以支持规格和原型探索。
- **一次性反馈轻处理**：错字、单个间距、颜色、裁切和局部对齐可以直接修复，不要求创建新版本、完整评审或完整记录。
- **证据优先于仪式**：已有截图、文件、用户反馈和项目事实足以判断时，直接使用，不要求重复填表。
- **自动修复优先**：发现可由现有事实解决的问题时直接修复并重跑定向检查，不先向用户索要流程确认。
- **只在必要时停下**：事实冲突、范围变化、权限/合规、关键品牌资产、不可逆取舍和正式批准动作才需要用户决策。

## 检查强度

| 变更规模 | 最小检查 | 可选检查 |
|---|---|---|
| 单个视觉细节或错字 | 目标页渲染、局部视觉自评 | 前后截图记录 |
| 一个区块或一个已有交互 | 受影响页 Q-P、事实一致性审计 | 定向 Q-S、完整十项视觉自评 |
| 页面结构、跳转、状态契约 | 定向 Q-S、受影响页 Q-P、事实一致性审计 | 完整 Q-S/Q-P |
| 产品事实、范围、接口或权限 | 正本同步、语义检查、事实一致性审计、受影响页 Q-P | 产品评审、估点 |

## 记录强度

- 一次性可逆小改可以只在回复中说明修改文件和检查结果。
- 会影响后续判断的视觉取舍写入 `prototypes/.design-decisions/`。
- 会改变产品事实、范围或下游工作的反馈写入反馈记录。
- 评审、批准、估点和新版本必须保留正式记录。
