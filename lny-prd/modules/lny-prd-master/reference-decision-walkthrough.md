# 产品决策自动走查

产品决策在规格和原型之前形成，先标记为“暂定”或“已确认”。规格与原型完成后由 Agent 自动回看是否兑现。走查不是重新发起一轮泛泛评审，只有发现偏离、冲突或不可逆取舍时才请求产品决策。

报告遵守 [`reference-check-report.md`](reference-check-report.md)，核心字段通过但 Q-S/Q-P 未完成时状态写“通过但待后续门禁”。

## 前置决策契约

在 `main_spec.md` 或当前项目工作台记录以下内容：

- 产品目标和目标用户
- 本次要解决的问题
- 本次范围和明确不做
- 优先级与成功标准
- 关键业务约束、品牌事实和不可逆取舍
- 允许由 Agent 自行决定的可逆事项
- 决策状态：暂定 / 已确认

已有批准事实直接引用。局部视觉反馈可以沿用已有决策，不重复创建决策契约。暂定决策足以支持规格和原型探索，已确认决策才作为交付范围和估点依据。

## 自动走查顺序

1. **目标兑现**：当前 Feature、页面和原型是否仍服务最初目标和目标用户。
2. **范围兑现**：是否遗漏本次范围，是否把明确不做的能力写进规格或画进原型。
3. **链路兑现**：Feature、AC、PAGE、API/EXT 是否形成可追溯闭环。
4. **页面兑现**：页面首要任务、主操作、信息层级和状态是否支持成功标准。
5. **视觉兑现**：原型视觉自评是否对照页面任务、视觉方向和关键资产，而不是只看通用审美分数。
6. **反馈兑现**：产品反馈是否已经同步到事实正本和所有受影响下游文件。

## 结果路由

- 全部通过 → 标记“自动走查通过”，可交付或进入下一动作。
- 发现可自动修复的偏离 → 回到责任步骤修复，再重跑受影响检查。
- 发现范围、目标、品牌、权限或不可逆取舍变化 → 暂停并请求产品决策。
- 只是 A 类视觉微调 → 只走目标页渲染、视觉自评和局部 Q-P，不重跑完整规格链。

## 输出

走查结果只报告：决策条目、对应证据、通过或偏离、修复路径和是否需要产品决策。不要把“建议再看看”当作结论。

有 `decision_contract.md` 或 `product_workspace.md` 时，可运行：

```powershell
python <skillDir>/modules/lny-prd-check/scripts/audit-decision-walkthrough.py <prdRoot>
```

脚本检查决策字段、状态和决策中引用的 PAGE/API/EXT/Feature 是否存在。没有决策工作台时返回 `DECISION_WALKTHROUGH: skipped`，不阻塞局部可逆修改。
