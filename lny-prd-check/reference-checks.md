# 检查表（文档性 / 功能性 / 产品就绪度）

执行三大块时 Read 本节。回归样例：技能包 `examples/mini-shop/`（只读）。

## 一、文档性检查

对根规格文档及明细目录的规范性、完整性、一致性做只读检查，不涉及原型实现。

> **检查顺序（须按下列小节依次执行）**：先确认 **结构壳齐全** → **编号与索引一致性**（格式/数量/唯一/清单↔文件夹）→ **内容格式** → **文档内交叉引用闭环**（含产品可评估链举证）→ **版本/台账** → 其它。  
> 编号事实源：`main_spec` **§2.1**（`STORY` / `FEATURE` / `PAGE` / `COMP` / `API` / `EXT`）。

### 1.1 结构完整性类

> **纯文档级、不读正文**：只确认文件/目录是否存在、是否落在约定位置。**禁止**打开正文核对章节标题或字段；章节与内容细项归 1.2～1.4。四份根规范须逐份过，不得只查 UI。

| 检查项 | 规则 | 不通过建议 | 优先级 |
|--------|------|------------|--------|
| 根规范文件存在 | 项目根存在 `main_spec.md`、`ui_manifest.md`、`api_spec.md`、`feature_spec.md`（缺哪份报哪份） | 缺则走 `/lny-prd-master` 或对应子技能补建 | 高 |
| 明细目录存在 | 存在 `ui/`、`api/`、`feature/`（可空） | 创建空目录或走对应步初始化 | 高 |
| 版本目录存在 | 工作版本对应 `versions/{v}/` 存在；有台账/单页时对应子路径目录存在即可（不读文件内容） | `/lny-prd-iter` / `/lny-prd-page` 补目录 | 中 |
| `ui/` 落点归属 | 凡 `PAGE-*.md`/`COMP-*.md` 须在 `ui/` 下，不得散落根目录或其它目录（只看路径，不读文件） | `/lny-prd-ui` 迁移 | 高 |
| `api/` 落点归属 | 凡 `API-*.md`/`EXT-*.md` 须在 `api/` 下（只看路径） | `/lny-prd-api` 迁移 | 高 |
| `feature/` 落点归属 | 凡 `FEATURE-*.md` 须在 `feature/` 下（只看路径） | `/lny-prd-feature` 迁移 | 高 |
| `pages_prd` 落点归属 | 单页 PRD 文件须在 `versions/{v}/pages_prd/` 树下（允许嵌套子目录；只看路径） | `/lny-prd-page` 迁移 | 中 |
| `prototypes` 落点归属 | 页原型 `PAGE-*.html` 须在 `prototypes/{终端}/` 下且 `{终端}` 与文件名终端编码一致（只看路径；有无文件见 1.6） | `/lny-prd-prototype` 迁移 | 中 |

### 1.2 编号与索引一致性类

> **只查清单登记册**：编号规则（§2.1）+ 编号数量（清单行数 = 对应明细文件数）+ 清单内无重复 + 清单 ↔ 文件夹双向一致且唯一。  
> **不查**文档正文里的交叉引用——归 **§1.4**。  
> **索引类优先级统一为高**（FEATURE / PAGE / COMP / API / EXT 同类断裂同等阻塞）。

| 检查项 | 规则 | 不通过建议 | 优先级 |
|--------|------|------------|--------|

| COMP 编号与索引 | `COMP-{三位序号}`；`ui_manifest` 清单：格式正确、无重复、条数 = `ui/COMP-*.md` 数；双向一致且唯一 | `/lny-prd-ui` 修正/去重/补文件或索引行 | 高 |

### 1.3 内容格式规范类

> 只查 **可读性与 Markdown/编码形态**，不查业务语义、实现越界或主文档↔API 对齐（该类历史项已废弃）。

| 检查项 | 规则 | 不通过建议 | 优先级 |
|--------|------|------------|--------|
| 编码与乱码 | `.md` 等规格正文须为 **UTF-8（无 BOM）**；不得出现典型乱码（大量 `�`、GBK 误读花码、无意义控制字符）；大面积不可读可升 🔴 | 以 UTF-8 无 BOM 重存并修复乱码段 | 中 |
| Markdown 围栏闭合 | \`\`\` / `~~~` 须成对；不得因未闭合导致后续正文被吞进代码块 | 补闭合围栏或拆开误并段落 | 中 |
| Markdown 表格格式 | 含表头的表须有分隔行（`\| --- \|`）；同表行列 `|` 数量明显不一致须报 | 补分隔行或对齐列数 | 中 |
| 标题层级连贯 | 同文件内标题层级不得明显跳级（如 `#` 后直接 `####`）；空标题（仅有 `#` 无文字）须报 | 调整层级或补全标题文字 | 低 |
| 链接与括号闭合 | Markdown 链接 `[]()`、图片 `![]()` 括号成对；明显残缺链接（有 `]` 无 `(` 等）须报 | 补全或删除残缺标记 | 低 |
| 空壳结构 | 连续多个标题下完全无正文/表/列表，或整节仅空白占位，影响阅读时须报 | 补正文或删空壳标题 | 低 |
| 图示围栏（若有） | Mermaid / 时序图等须落在已闭合代码围栏内，且围栏语言标记与内容类型大致匹配（如 `mermaid`） | 补围栏或修正语言标记 | 低 |

## 二、功能性验收

以用户视角对照规格对原型做走查。只读输出评价与委派建议，**不回写文件**。模型不当老板：不判断「该不该做」，只报可判定项。

### 无原型时的行为（必读）

当工作版本下 **不存在** 任何业务页 `prototypes/{终端}/PAGE-*.html`（不含仅有 `index.html`/`map.html`）时：

1. **跳过** 本节逐项对照（不编造失败项）。
2. 输出 **一条** 须关注项：原型缺失，本轮功能性验收跳过；优先级 **中**（用户目标是演示则可升 **高**）。
3. 委派：`#序号` → 建议 `/lny-prd-prototype`（⑥）；缺 `pages_prd` 且非 `ui直出` 则建议先 ⑤。**等用户确认**后再交总控执行。不要让 ⑦ 空报完事，也不要在报告结束后静默刷原型。
4. 若仅有壳层汇总而无业务 `PAGE-*.html`，同上视为「无业务页原型」。

### 功能性验收执行步骤

1. **先做「无原型」门禁**；不通过则结束本节。
2. 读取 `main_spec` 成功怎么算 / 明确不做（未填则不拿「该不该做」压人）、`ui/`、`api/`、`feature/`、`pages_prd`、`prototypes/`。
3. 先走 **规格外 / 文案 / 主路径**，再走 **实现符合规格**（原 2.1～2.8 收成一块）。
4. JS 问题以静态检索为底线；有浏览器再辅以 Console。

### 2.1 规格外

| 检查项 | 规则 | 不通过建议 | 优先级 |
|--------|------|------------|--------|
| 明确不做 | 原型或规格是否做进 `明确不做`（未声明则跳过本项） | 对应 ②③④⑥ **删超范围实现/规格**。**禁止**为了过检查去改 `main_spec`「明确不做」列表（除非用户明确要求改范围） | 高 |
| 无来源主交互 | 是否出现 STORY/FEATURE 都未提及的主按钮或整页 | 补 FEATURE/PAGE 或从原型去掉 | 高 |

### 2.2 文案

| 检查项 | 规则 | 不通过建议 | 优先级 |
|--------|------|------------|--------|
| 文案来源 | 可见文案须能在 PAGE/COMP/`pages_prd` 找到来源 | ②⑤ 补规格或 ⑥ 改文案 | 中 |
| 文案通顺 | 不通顺、与规格用词冲突则报；禁止为了检查去编文案 | ②⑤⑥ 对齐用词 | 中 |

### 2.4 实现符合规格

对照规格做没做，收成一块（含壳层与套件）。

| 检查项 | 规则 | 不通过建议 | 优先级 |

## 三、产品就绪度检查（不计 SP）

> 第三大类，与文档性、功能性并列。**不算故事点**。

### 3.1 产品可评估链（阻塞「不可估」·虚引用）

> **虚引用规则**：不在此重复开列与 §1.4 相同的问题条目；根据 §1.4（及必要的 §1.2）结论判定 **可估 / 不可估**。  
> **计数**：汇总「共 N 个问题」时，**3.1 不计条数**（避免与文档性双计）；仅输出结论与「缺口引用 → 文档性条目」指针。

| 判定依据（文档性来源） | 不可估条件 |
|------------------------|------------|
| §1.2 / §1.4 故事与 STORY↔FEATURE | 无有效 `STORY-*`，或故事未挂 FEATURE/框架承接 |
| §1.4 FEATURE↔AC | 任一 **active** FEATURE 缺 AC 表（有数据却未挂 API/EXT 且未写「无」） |
| §1.4 Feature↔页面/接口 | active FEATURE 关联页面/接口为空且非显式「无」，或孤儿引用 |
| §1.4 非静态 PAGE↔API | 非静态页既无 API 又未说明静态 |
| §1.4 API 元数据完备 | 纳入口径的 API 缺服务对象/数据操作形态/第三方联动/特殊通道/响应形态，或联动「是」无 EXT |

报告形态示例：

```
── 3.1 产品可评估链 ──
- 可估 / 不可估：不可估
- 缺口引用：见 #2、#5（不另占序号）
```

档位分值见 `lny-prd-sp/reference-weights.md`。本步 **只核能否采集，不计分**；旧枚举只读识别为同档，**禁止**落盘改字。`_shell` 不计 FE。
